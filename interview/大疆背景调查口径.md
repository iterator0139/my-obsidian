## 四、负责内容（详细版）

### 1. 整体架构设计

- 设计了三 Agent 架构：意图识别路由 → IG Agent（知识查询）/ Text-to-SQL Agent（数据查询）/ 复杂归因诊断 Agent（Plan/Execute 多 Agent）
- 确定了固定链路 workflow 化、开放长程任务多 Agent 化的架构策略

### 2. Plan/Execute 多 Agent 架构设计与实现

- 将复杂归因诊断任务拆分为先规划后执行的 DAG 架构
- 设计 Planner → SubAgent 委派 → Summary 汇总的调度机制
- 解决长程任务中上下文膨胀和注意力失焦问题
- 设计子任务通信机制（通过上下文传递 role/instruction/input/output/dependency，非 A2A 协议）

### 3. 四层记忆管理机制设计与实现

- 短期记忆：当前 session 对话历史，保持多轮交互连续性
- 工作区记忆：保存 plan、todo、关键中间状态，防目标漂移
- 文件系统记忆：外置大工具结果（SQL 查询、日志、报告），防上下文膨胀
- 长期记忆：沉淀用户偏好和成功任务经验，可检索复用

### 4. 工程治理与稳定性

- 规划校验机制：结构校验（JSON schema、DAG 合法性）+ 语义校验（rubric 评估）
- 中间流程重试、失败捕获与传播
- 上下文压缩策略（70% 阈值触发，保留前 10% + 后 10%）
- Plan 结构正确率从初版约 50% 提升到接近 99%

### 5. 方案 review 与交付把关

- 负责 RAG 链路的 Agentic RAG 升级方案 review
- 负责 Text-to-SQL 多阶段流水线（query 改写 → schema linking → 列值探测 → SQL 生成）方案 review
- 与算法、产品、运营一起定义评测标准和 bad case 迭代流程

### 6. 业务需求到技术方案的转化

- 从运营工作流中识别三个低效环节：知识获取、数据查询、归因诊断
- 将业务需求转化为可落地的技术方案
- 覆盖项目全生命周期：需求分析 → 架构设计 → 方案 review → 上线优化
