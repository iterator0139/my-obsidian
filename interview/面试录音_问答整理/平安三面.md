## Q4. 真实场景里的上下文管理和架构

**问题：** 取一个真实场景，说明整个 Agent 怎么设计、上下文怎么管理。尤其 ReAct 模式下找不到目标工具时怎么优化流程或目标工具？

**回答：** 以 ROI 下降归因诊断为例。它的执行路径可能是先查流量规模，再查曝光、点击、CVR 转化数据。这个路径是规划出来的。

长程任务里，工具结果会越来越大，中间思考结果也都在短期上下文里。这有几个问题：第一个是子任务目标可能和原始任务目标发生漂移。比如原本想看 ROI 下降原因，但后面的步骤可能引入了和目标不相关的动作，比如想看用户画像。

针对目标漂移，我们通过工作区记忆机制解决。每个 Agent 在最开始做 plan 时，把目标和 todo list 持久化到文件里。在长程任务执行前，我们周期性做目标注入，把目标放在 prompt 最前面，缓解目标漂移。

第二个是上下文膨胀会导致模型推理效果下降和注意力失焦。我们基于阈值限制做压缩，保留前 10% 和后 10% 上下文，把中间完整上下文做压缩后再拼回短期记忆。

第三个是工具结果外置。每个工具结果回来后，我们会做工具结果摘要，同时把原始结果写到文件系统里。短期上下文只保留摘要和引用信息，不保存原始工具执行结果。

**问题：** 你能解释一下 QKV 的计算逻辑吗？

**回答：** 大模型 attention 机制希望捕获每个位置 token 和其他位置 token 的关系。它会对每个位置做特征抽取，包括 Q、K、V。

Q 是当前位置 token 用来检索的特征，K 是用来匹配其他位置 token 的特征，V 是当前 token 抽取出的 value 表征。attention 的计算就是用当前位置的 Q 去查询其他位置的 K，做相似度计算，得到当前位置和其他所有位置的注意力权重，再通过权重和 V 做加权聚合，得到当前位置的表征。

## Q8. 什么是梯度和梯度下降

**问题：** 你了解梯度下降吗？什么是梯度？

**回答：** 梯度代表变量变化的方向。比如某个参数和 x 有变化关系，梯度代表 x 变化的方向。

在函数优化里，比如 deep learning 和机器学习，是对目标函数优化，通过反向传播优化参数。我们有一个目标函数，希望它降到最小，所以需要计算梯度，算出方向之后，把参数往 loss function 最小化的方向更新。

## Q9. 线上 CPU 异常怎么处理

**问题：** 线上环境经常遇到 CPU 异常。如果遇到这种情况你怎么处理？哪些情况会导致 CPU 利用率异常？

**回答：** 首先可以在服务器上通过 top 看线程或进程使用情况，找到 CPU 异常的线程或进程，再根据不同服务语言，用工具查看堆栈调用情况。

第二种是借助火焰图。Go 这边可以通过线上采样堆栈的方式，用图形化方式定位代码异常。

原因包括死循环、CPU 密集型代码、GC 问题，也可能是线上 pod 混部，受到其他服务影响。

## Q11. 做过哪些性能优化

## Q12. 如何设计内存池

**问题：** 如果用 Go 设计一个内存池管理模块，大概有哪些思路？池具体用什么结构？

**回答：** 线上主要用 Go 里的 sync.Pool。自己设计的话，可以有一个对象池，给固定大小。因为要考虑并发安全的获取和删除，可以用数组来做。

如果要减少并发冲突，可以做分段锁机制，把 pool 分成多个区域，每个请求通过分区操作只到某一个分区的数组里获取对象，锁竞争会少一点。

对象放回时，需要区分 in-use 和空闲区间。使用完的对象再标记成空闲状态。放回时结构体需要先清空，不然会带着之前的数据。
