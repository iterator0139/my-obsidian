# 网易二面｜问答整理

## Q1. Agent 项目框架

**问题：** 这是不同的 Agent 吗？用了什么框架？支持 MCP 或 Skills 吗？

> 整理备注：此处说话边界可能需要回听确认。源文件开头缺少完整寒暄，直接从候选人项目介绍后半段开始。

**回答：** 第二个项目经验的话就是作为一个主导者然后落地了这样一个商家运营智能助手的这样一个项目，然后去解决广告运营在工作中他们知识获取然后数据查询以及归因诊断这三个环节的一个效率低下问题。基于他们的一个场景的一个痛点去通过设计多级的一个混合 agent 架构，包括四级的一个记忆机制，然后第三个是一个 plan is killed这样一个多智能体的一个工作模式。

它是不同的。首先第一个的话我们那个Test2Circle它是一个workflow的形式，所以这里的话我们是采用了那个longchain的一个框架。然后对于那个第一个那个React IE机那块是我们自己手写的一个React的一个控制循环，然后对于PlanetXQ的这也是我们自己写的一个调度的一个机制。

MCP和一些TOS是有的，但是Skills暂时我们还没有接入，最近是准备开始做一些研发的一些计划。MCP要接入到这个自研的WebAgent的话，主要还是通过它的一个描述以及它的一个上下文的动态注入来去做一个这样的一个管理。

## Q2. Skills、注册中心和鉴权

**问题：** Skills 怎么加载？用户动态加 MCP 或 Skills 怎么实现？MCP 鉴权怎么做？

**回答：** Skills它也是一个技能体的组合封装，它其实也是跟MCP的概念有一点类似。它也会有一个技能描述的说明，然后作为一个完整的上下文，比如它有多个Skills，然后去一次性加载出每一个Skills的上下说明，基于这个说明模型去进行Skills的选择。选择好了之后再读取Skills目录以下的内容，进行详细文档的阅读。

动态加的话，我们可能要引入一个注册中心的概念，就是把工具的注册和注入解误出来。每一次新加一个Skills或者MCP，就往注册中心里面注册。通过一个接口暴露出来所有Skills和MCP的原信息。每一次做System Prompt的时候只需要拉取这个接口，就能够获取所有注册好的MCP和Scales。后续如果要做优选，也可以在注册中心外面加一层Torselector。

每次动态读取也可以做缓存，因为第一次拉曲之后你就可以不用再拉曲了，这部分就是固定的上下弯。

鉴权的话，三方MCP可能需要一些健全。假设系统是中性化或者用户化，我们需要让用户在他的MCP配置里面给他的token以及需要的健全信息，让他管理在我们的MCP配置里面。每次MCP调用的时候直接读取已经配置好的健全信息，传到MCP完成健全。

## Q3. 参数预填和转发 MCP

**问题：** 三方 MCP 参数想预填，比如图像分辨率固定 2K，除了写 prompt 怎么办？转发 MCP 还能做什么？

**回答：** 我理解这个时候我们可以去直接在参数的这个schema，我先给它预定好预填好一部分，然后用这个作为它的一个初始化的这样一个参数，然后再去生成这样我们最后完整的参数，然后再去调用。可以做一个转发对不对，我们自己实现一个MCP转发MCP，然后里面去控制参数的生成是不是就可以了。

转发MCP的实现，首先让模型知道这是一个某某MCP的转发MCP，它必须通过调用这个MCP来实现那个功能。这个MCP里面已经预制好默认参数了，模型调用转发MCP就可以让预填参数生效。

还能做缓存参数的教验，参数的教验是可以做一个中间键。第二个回报这里也可以做输入输出的治理，输入schema和输出内容的理解，一些Summary或者摘要。第三个可以做MCP的降级超持这些控制。

## Q4. 多模态知识库

**问题：** 做多模态知识库会涉及哪些问题？文本、图片、视频、音频怎么存储和检索？

**回答：** 多模态知识库要解决的问题是能够把多模态的信息给存储，且高效的解锁和利用。多模态数据涉及图片、语音、文字、视频。

检索目标首先是能够根据关键词进行相似度检索，第二个是能够进行语意的文本、bmr5的检索，第三个是要支持filter能力，包括原信息filter。所以基于这些考量，还是只能通过ES检索和向量数据库这两种形式来保存数据。

文本为了满足相似度和BMW捡索，直接放ES和vector database。图片可以放在vector space里面，也可以给每个图片构建Caption，构建图片描述以及原信息，用ES存储下来。视频的话可以通过视频和文本描述形成映射，也可以把视频切成按针，组合成多集的向量解锁结构。音频也是通过向上检索它的索引，然后通过s3或者大数据存储关联外部存储地址。

## Q5. 以图搜图和 caption 方案

**问题：** 用户搜索可能输入图片，以图搜图、图片搜视频怎么做？把图片转文字有什么问题？

**回答：** 这里有个前提，就是咱们的多模态的embedding表征一定是要联合训练出来的。不然的话你的检索就是完全没有意义的，一定要把它们在一个限量空间表征出来。

如果把图片生成文本描述，就变成文本了。这个方法的问题首先是成本可能比较高，因为需要为所有图片做文本抽取。其次准确性依赖于图片描述的完整性和准确性，这中间肯定会有损，因为事物描述很难面面俱到地用文本表达准确。第三个是检索中涉及embedding转换，有耗时成本。

## Q6. 原始数据、元数据和统一实体

**问题：** 原始视频图像音频怎么存？元数据、多租户、资产管理接口怎么设计？统一实体叫什么？

**回答：** 原始数据要不要存，应该根据应用场景决定。需要在应用上展示原始数据的话肯定要存；如果不需要真实内容展示，引用一个外链就可以了。如果需要真实内容展示，图像视频音频可以存储在S3这种外部的分布式存储上，通过地址关联。文本直接通过ES就可以。

多租户、资产属于谁、描述、更新记录这些，相当于知识库概念。每一个知识库每一个文件可能都有所属权，可以通过外置关联、表跟表之间设计关联来解决。也可以直接在索引里面加角色字段、原信息。

如果用户想list资产，有管理界面，那么一部分存储服务用户展示诉求，可以通过MyCircle或者ES做查询。另一部分向量数据库存储用来做检索实现。更新时相当于DB和向量库双写，通过唯一ID关联。

统一实体的话，把语音、视频、图像、文章都看成一个一个知识，就给他作为一个knowledge这样的概念。每个knowledge有一个唯一ID。

## Q7. 大模型在检索中的作用

**问题：** 大模型可以在哪些环节提升多模态检索效果？

**回答：** 如果只是精确检索，比如搜包含某某东西的文档，不需要用大模型的智能能力，关键词匹配机制直接返回就可以。问答场景才需要上下文补充，再做回答。

多模态为了保证效果，可以过一遍金牌。比如召回20个图片，通过大模型做一次精选select，只返回top5或top10。还可以做query改写，因为query侧和存储侧表针不一致，用query改写能力把query改写成更加符合存储里面表针的形式。

入库过程中，大模型可以抽取摘要信息和原始属性作为原信息。原始文章不应该改写，因为你的写入机制是由存储数据库决定的，唯一能变的是数据组织和内容。

## Q8. embedding、专有名词和游戏角色

**问题：** embedding 模型怎么选？专有名词效果不好怎么办？游戏图片里的角色模型不认识怎么办？

**回答：** 选择模型要看数据规模、向量模型最大支持长度、推理实言、对检索链路耗时的容忍度、准度问题，以及多模态是统一表征还是分开模态表征。文本类我熟悉的有BGM、bg1bert、mrbert，但具体让我选可能记得不太清楚。

内部专有名词效果不好，只能去做一些微调，构建数据集做embedding微调，做正负样例训练自己的embedding。样例特别少的话，就做一些种子的LAM数据合成，通过prompt约束、fuel short、一批种子案例，借助强模型的数据合成能力。

游戏图片角色如果模型不认识，第一个可以人工标注，但成本高。不行的话依赖模型判别能力。公司内部还有代码、设计稿这些资产，可能从里面挖掘语意信息，但这个问题有点难，可能需要深入到case和场景里面才能想。

## Q9. MCP tool 设计

**问题：** 多模态检索要给 Agent 使用，通过 MCP 协议暴露 tool，怎么设计？

**回答：** 首先是全线教验。因为有租户逻辑，可以在MCP第一次调用、没有进入真正向量检索前，通过健全控制它对某个资源的访问。

tool设计的话，第一个是用户维度信息，包括user ID、部门信息这些。第二个是用户query，query是多类型的，因为有多模态概念，可以抽象成结构体。对于文本query只需要文本query，如果是资源类就需要资源地址以及描述。第三个是查询条件，一个filter字段，里面可以有多个filter条件组合，包括字段名和value。第四个是agent上下文信息，比如现在执行的任务是什么、task、目标goal这些字段，后续对query改写会有作用。

转发MCP还能做什么，我想一下，比如缓存参数的教验，参数的教验是一个相当于也是可以做一个中间键了，就是你可以做一个模型生成的参数的一个教验。第二个的话回报这里也可以给它做一个就相当于输入输出的一个治理，你可以做输入的schema和你输出内容的一个理解的一些 Summary或者说是摘要。第三个的话你可以在这里做一些MCP的这样一个降级超持这样一些控制。

## Q5. 多模态知识库设计

**问题：** 如果要做多模态知识库，会涉及哪些问题？怎么存储、检索文本、图片、视频、音频？

**回答：** 首先多模态的知识库它要解决的问题是能够把多模态的信息给存储，且高效的解锁和利用，这是它的一个主要要解决的问题。然后在这个背景下面我们会需要去接入多模态的数据，然后多模态的数据涉及到它的图片语音，然后文字视频。

检索的目标首先是能够要根据关键词进行相似度的检索，第二个是要能够进行语意的文本，bmr5的检索，第三个是它要能够支持filter能力，包括你的原信息的filter能力这些都是需要支持的。所以基于这些考量我们还是只能通过ES检索和向量数据库这两种形式来保存我们的一个数据。

文本我们为了去满足它的相似度和BMW捡索我们直接就放ES和vector database。图片这里我们因为现在图片的多模态表征也已经比较成熟了，然后我们也是可以把它放在vector space里面。其次的话我们可能需要给每个图片去给它构建一个Caption，给它构建好这样一个图片的描述以及它的一些原信息，我们也可以用ES给它存储下来。

视频的话我想的话可能就是首先通过视频和那个文本的描述形成一个映射关系，如果只是要检索它的一个视频源的话，我们就可以通过这种方式文本解锁去做。第二个的话如果要做向量解锁的话，我们可以把视频切成按针去切，然后给它组合成一个多集的这样一个向量解锁的结构。音频也是通过向上去检索它的一个检索的，所以然后再通过s3或者这种大数据存储这种让它关联到我们这样一个外部存储的地址上面。

## Q6. 以图搜图、多模态 embedding 和 caption 方案

**问题：** 用户搜索不一定输入文字，可能输入图片。以图搜图、图片搜视频怎么做？如果用图片识别转文字有什么问题？

**回答：** 这里首先这里有个前提，就是咱们的多模态的embedding表征是一定是要联合训练出来的。就是不然的话你的检索就是完全没有意义的。一定是要把它们在一个限量空间给它表征出来，不然你的限量检索就是毫无意义的。

如果是通过图片识别这样的技术来，其實就生成了一段文字就變成文本了。首先它的一個成本可能會比較高，因為這是第一個問題，就是你需要為所有的圖片去做一個文本的抽取。其次就是你的準確性依賴於你的圖片的描述的一個完整性和準確性，然後這中間是肯定會有損的，因為你的一个事物描述这个是很难把它给面面俱到给他描述的。第三个的话，因为你是检索中涉及到你的一个embedding的转换，和embedding转换这一块是有你的一个耗时的一个成本在里面。

## Q7. 知识实体、元数据和管理接口

**问题：** 文档、图像、视频这些原始内容和元数据怎么存？如果用户要 list 自己有哪些资产，怎么设计统一实体？

**回答：** 原始人类这些东西怎么存，这个肯定是要存。因为我们也如果需要，我想一下应该根据应用场景来决定存不存。像如果你需要去在应用上面给它做原始数据的展示，这肯定是需要的。所以如果你不需要真实的内容的展示，那么我们就引用一个外链就可以了。如果你需要真实内容的展示，像刚刚说的这些图像视频音频，我们就是可以存储在这种S3这种外部的这种分布式存储上面，然后通过这个地址去给它关联好就可以了。

比如那些多租户的数据，这个资产属于谁的，还有一些对这个东西的一些描述原新鲜描述更新记录这些东西怎么成的。相当于这是一个知识库的概念了。每一个知识库每一个文件它可能都是有一个所属权。我们可以通过外这种关联就是表跟表之间设计的关联中以来解决这个问题。

有一个操作界面的话，我把这个所有的这个语音啊，然后视频啊，图像啊，文章啊，这些我们都看成一个一个知识吧，就给他作为一个一个knowledge这样的一个概念。因为本身也叫知识空盘，然后这个知识有一个每个知识有一个ID。

## Q8. 大模型在多模态检索中的作用

**问题：** 多模态检索里，大模型可以在哪些环节提升效果？

**回答：** 我的理解是这样，就是你只有对问答场景你才需要去做这样一个上下文的这样补充，然后再去做这样一个回答。但你如果对于这种精确检索就像我们搜某一个文档是什么，包含某某东西的文档有哪些这种场景的话，就是要精确检索，不需要用到大模型的它的一个智能能力。

或者说因为这里涉及到多模态，然后在多模态的话我们去保证它的效果，我们可以过一遍金牌的概念。就比如我们解锁到了一堆图片或者说比如我们找回了20个图片，然后我们通过大模型然后去做一次精选做一次select，让它只返回top5或top10。

还有的话就是可以做你的query改写了。query改写的话因为天然的话你的query册和你的存储册它的一个表针是不一致的，所以你可以用你的query改写的能力去把你的query改写成更加符合你的存储里面表针的这样一个形式。

入库的话主要其实因为你的写入机制是已经控制好的，你唯一能变的就是你的一个数据的一个组织和它的一个内容。你要去改写它的那个原始文章也不合理，所以你只能去抽取出它的一个摘要信息，然后你的一些原始的属性去作为原信息。

## Q9. embedding 模型、专有名词和内部游戏角色

**问题：** embedding 模型怎么选？专有名词检索精度下降怎么办？内部游戏角色、按钮、图片模型不认识怎么补充？

**回答：** 我们肯定是要根据你的一个query和你的一个数据规模，然后看这个向量模型它最大支持的一个大小长度是多少。第二个的话是它的一个推理的一個實言，我们想要看一下我们对整个检索链路也好，因为最终的话你需要去做一个embedding的预估然后再去做检索。第三个的话就是我们的一个准度问题。第四个问题就是我们的一个 embedding 表征准确度的问题。

文本类的话具体来说我可能熟悉的就是有一些像BGM bg1bert，然后那个才有个什么叫mrbert。你现在具体让我来选的话也可能记得不太清楚了。

对于公司内部的一些概念，内部的黑化，这个只能去做一些微调了，就构建一些数据集去做那个embedding的微调。样例特别少的话，那你就只能去做一些种子的LAM的一些数据合成了。然后通过一些prompt的一些约束，然后你给他一些fuel short，然后你通过一批种子案例，然后借助于墙模型的这样一个数据合成的能力。

图片游戏的图片里面可能涉及角色，如果构建的时候没把metadata构建出来，那第一可以人工标注，人工标注成本比较高。人工标注不行的话那就还是要依赖那个模型的一个判别能力。公司里面其实有很多其他的一些资产可以从中里面挖掘出这个东西，有可能从代码或者设计稿这些东西里面去提取，但这个问题可能需要深入到那个case里面那个场景里面才能去想一下。

## Q10. 把多模态检索暴露成 MCP tool

**问题：** 多模态检索给 Agent 使用，要通过 MCP 协议暴露出去，这个 tool 怎么设计？

**回答：** 首先第一個的話就是肯定是剛剛提到的那個全線的一個教驗。因为我们刚才也提到那个全线的租户的那套逻辑，我们也可以有一张实体表来做一个东西。所以我们其实在它做MCP第一次调用没有进入到真正的向上检索的时候，我们就可以通过这样一个健全的这样一个控制，然后去控制它对某一个资源的这样一个访问。

核心是那个tours怎么设计的话，首先第一个的话就是用户维度的信息，包括他的一个user ID，然后它的一些部门信息这些。第二个的话就是用户的query，query的话它其实是一个多类型的，因为它是有一个多模态的概念。所以这个时候我们可以把它抽象成一个结构体。对于文本的query它就只需要那个文本的query就可以了。

第三个的话应该是查询条件，一个filter的这样一个字段，filter字段里面可以有一个多个filter条件的组合，它包括你的一个字段名和你这个字段的一个value值。第四个你的上下文信息，比如他现在执行的任务是什么，然后他的一个task，然后他的一个目标go这样一些字段，可以对他的一个query改写可能后续会有一些作用。

**回答：** 问一下您这边是具体是做奶哪个业务方向，因为听您这边描述的好像也比较广。第二个的话就是我这个岗位是跟这一块也是强相关还是别的安排。

> 面试官介绍：刚才聊的是实际业务，支持户的构建、检索之构建维护是其中一个重要方向，公司还有上层 Agent、CodingAgent。

# 网易二面｜问答整理

## 开场

> 整理备注：源文件开头缺少完整寒暄，直接从候选人项目介绍后半段和面试官追问开始，前置边界可能需要回听确认。

## Q1. Agent 项目用了哪些框架

**问题：** 你们不同 Agent 是一个多 Agent 体系吗？用了什么框架？

**回答：** 它是不同的。第一个 text-to-SQL 是 workflow 形式，所以采用了 LangChain 框架。第一个 ReAct Agent 那块是我们自己手写的 ReAct 控制循环。Plan Execute 也是我们自己写的调度机制。

## Q2. 是否支持 MCP 和 Skills

**问题：** 这里面有支持 MCP 或 Skills 这样的能力吗？

**回答：** MCP 和一些 tools 是有的，但是 Skills 暂时还没有接入，最近准备开始做一些研发计划。

MCP 接入到自研 WebAgent，主要还是通过它的描述和上下文动态注入来管理。每一次模型调用时，会有 MCP 的功能描述、参数的拼接，让模型自行选择，再进行 MCP 调用。

## Q3. MCP 元信息是不是都塞到 System Prompt

**问题：** 是把所有 MCP 的元信息全部塞到 System Prompt 吗？有参考过其他开源 Agent 怎么实现吗？

**回答：** 现在是这样的。我了解到大部分也是这种模式，没有太多做 MCP 优选的环节。大部分还是在自己的框架里把 MCP 描述做简略描述，作为 prompt 注入。

## Q4. Skills 怎么加载

**问题：** Skills 如果要做，怎么加载？

**回答：** Skills 也是一个技能体的组合封装，跟 MCP 概念有点类似，也会有技能描述说明。

通过技能描述作为完整上下文，如果有多个 Skills，就一次性加载每个 Skill 的上下文说明。模型基于说明选择 Skill。选择好 Skill 后，再读取 Skill 目录下的内容，做详细文档阅读，了解具体怎么使用，然后再执行动作。它是渐进式加载。

## Q5. 用户动态增加 MCP 或 Skills 怎么做

**问题：** 用户希望动态加 MCP 或 Skills，你觉得怎么实现？

**回答：** 可能要引入注册中心，把工具注册和注入解耦出来。每新增一个 Skill 或 MCP，就往注册中心注册。

注册中心通过接口暴露所有 Skills 和 MCP 的元信息。每次构建 System Prompt 时，拉取接口就能获取所有注册好的 MCP 和 Skills。后续如果要做优选，也可以在注册中心外面加一层 tool selector。

每次请求动态读取 MCP 和 Skill 可能有点多余，可以做缓存。第一次拉取之后，如果上下文固定，就不用每次拉取。

## Q6. MCP 鉴权怎么处理

**问题：** MCP 可能有第三方 MCP，需要鉴权。中性化或用户化系统里怎么做？

**回答：** 需要让用户在 MCP 配置里管理 token 和鉴权信息。每次 MCP 调用时，读取已经配置好的鉴权信息，通过鉴权信息传到 MCP，完成这一次鉴权行为。

## Q7. MCP 参数预填怎么实现

**问题：** 比如第三方生图 MCP 有分辨率参数，我们希望固定生成 2K，不只靠 prompt 告诉模型，有没有更好的方式？

**回答：** 一开始我想到可以在参数 schema 里预定义好一部分，作为初始化参数，再生成完整参数后调用。

如果 MCP 调用完全由模型自主编排，可以做一个转发 MCP。我们自己实现一个 MCP 转发层，控制参数生成。模型知道这是某个 MCP 的转发 MCP，必须通过调用这个 MCP 实现功能；转发 MCP 里预置默认参数，然后再转发到第三方 MCP。

这个转发 MCP 还可以做参数校验、输入输出治理，比如输入 schema、输出内容理解或摘要，也可以做 MCP 降级、超时控制。

## Q8. 多模态知识库涉及哪些问题

**问题：** 如果要实现多模态知识库，会涉及哪些问题？

**回答：** 多模态知识库要解决的是把多模态信息存储，并且高效检索和利用。要接入图片、语音、文字、视频这些多模态数据。

核心目标包括根据关键词做相似度检索、语义文本和 BM25 检索、支持 filter 能力，包括元信息 filter。所以需要 ES 检索和向量数据库两种形式来保存数据。

文本可以通过 ES 和 embedding 导入。图片可以放在 vector space，也可以给每个图片构建 caption，构建图片描述和元信息，用 ES 存下来。视频和音频也类似，可以构建文本描述的语义检索库，再构建向量表征检索库。

视频方面我没有特别多了解，但可以按帧切分，组合成多级向量检索结构，实现 query 和视频某一片段 match。

## Q9. 用户输入不一定是文字，图搜图或图搜视频怎么做

**问题：** 用户搜索时不一定输入文字，可能输入图片。以图搜图、以图搜视频怎么做？

**回答：** 前提是多模态 embedding 表征最好是联合训练出来的，文档、图片之间在一致的向量空间。不然向量检索没有意义。

还有一种方式是转成 query text。比如以图搜图时，用户图片先通过视觉语言模型生成文本描述，然后把文本转成 embedding。构建图片库时，也把图片通过视觉模型抽成文本描述，再把文本描述和图片 ID 关系存到 embedding 数据库里，通过转换一层做检索。

但这种方法有问题：建库成本高，需要为所有图片做文本抽取；准确性依赖图片描述完整性和准确性，中间肯定有损；检索时涉及 embedding 转换，有耗时成本。

## Q10. 搜索结果需要结构化返回怎么做

**问题：** 用户希望搜索结果结构化返回，比如告诉他原始文档位置、视频位置，怎么做？

**回答：** 可以通过元信息实现。建库时把每个文档、图像、视频对应的数据源、来源网页链接存下来。检索拿到结果后，就有数据来源。

存储主要分两大类：ES 存储和向量数据库。文本存在 ES 和向量库。图像 embedding 存向量库。视频可以构建多个索引，比如帧粒度索引、分钟级别索引，通过父子关系构建多级查询机制。音频也类似，通过向量数据库检索片段或文档，再通过片段关联的外部存储源读取原始数据。

原始视频、图像、音频是否存，要看应用场景。如果需要在应用里展示原始内容，就要存，可以存在 S3 这种分布式存储上，通过地址关联；如果只需要引用，可以存外链。文本可以通过 ES。

## Q11. 多租户、资产管理等元数据怎么存

**问题：** 多租户数据、资产属于谁、描述、更新记录等元数据怎么存？用户要 list 自己有哪些资产怎么做？

**回答：** 这是知识库概念。每个文件、知识可能有所属权和访问权限。

可以在索引里加角色字段等元信息，检索层就做权限控制；也可以通过 database 从购买、设计表之间的关联来做管理。如果不在检索侧做，就需要外置控制层，检索回来再做权限控制，但这样会影响召回率，所以更好的方式是在检索和存储侧就做。

如果要提供管理界面，比如展示用户上传过多少视频、文档，可以用 MySQL 或 ES 做查询。向量数据库服务检索，管理信息存在 DB 里，更新时相当于双写。通过唯一 ID 关联。

可以抽象一个统一实体，所有语音、视频、图像、文章都看成一个 knowledge，每个 knowledge 有唯一 ID。

## Q12. 大模型在知识检索里能起什么作用

**问题：** 如果引入大模型，大模型在知识检索里有什么作用？哪些环节能提升检索效果？

**回答：** 如果只是精确检索，比如搜包含某某东西的文档，不一定需要大模型。问答场景需要用大模型做上下文补充和回答。

多模态检索里，大模型可以做重排。比如召回 20 张图片后，用大模型精选 top5 或 top10，做效果卡控。

还可以做 query 改写。因为 query 侧和存储侧表征不一致，可以用 query 改写能力，把 query 改成更符合存储表征的形式，帮助更好召回结果。

入库过程中，大模型可以做元数据生成，抽取摘要信息和原始属性，作为元信息。

## Q13. 选择 embedding 模型要看什么

**问题：** 多模态检索场景下，选择 embedding 模型要考虑哪些维度？

**回答：** 首先看数据规模。第二看向量模型最大支持长度。第三看推理时延，因为在线链路需要做 embedding 预估再检索，要根据时延容忍度选择。第四看准确度，尤其是多模态场景，是用统一多模态表征还是分开模态表征。还要看 query 和 query、query 和图片之间相似度评分的表现。

业界具体模型我文本类了解比较多，比如 BGE、bert 相关。语音、图片类了解不太多，所以具体让我选可能记不太清楚。

## Q14. 内部专有名词检索精度下降怎么办

**问题：** 向量检索里对内部专有名词精度下降，比如游戏内部概念、角色名、门派词，怎么补充？

**回答：** 可以做 embedding 微调，构建数据集做正负样例训练，训练一版自己的 embedding。

如果黑话样例特别少，可以通过种子样本做 LLM 数据合成。给一些 few-shot，通过强模型的数据合成能力生成一批数据。

## Q15. 模型不认识游戏图片里的角色怎么办

**问题：** 游戏图片里有内部角色，商业模型不认识，比如某个角色或按钮，怎么让检索更有效？

**回答：** 一种方式是元信息注入，通过关键词匹配找到。但元信息怎么来是关键。

如果游戏是内部开发，公司里有代码、设计稿、资产等其他资料，可以从这些资产里挖掘。比如挖掘图片和语义信息的 pair，然后做联合训练。

怎么保证挖掘质量，需要深入具体 case。可能要对数据源做控制，或者从反方向 filter 掉明显不匹配的语义；也可以人工 filter 或规则 filter。但这个问题比较依赖具体数据来源和场景。

## Q16. 多模态检索作为 MCP 暴露给 Agent，tool 怎么设计

**问题：** 多模态检索做出来后，要给 Agent 使用并通过 MCP 暴露出去，tool 怎么设计？

**回答：** 核心参数包括几个部分。

第一是用户维度信息，比如 user ID、部门信息，用于鉴权和权限控制。第二是 query 信息，因为是多模态，可以抽象成结构体：如果是资源类型 query，需要资源地址和描述；如果是文本 query，只需要文本 query。第三是查询条件 filter，包含字段名和 value，可以支持多个条件组合。第四是 Agent 上下文信息，比如当前任务、目标，这些对 query 改写可能有作用。

权限校验可以在真正进入向量检索前，通过实体表控制某个用户对某个资源的访问。
