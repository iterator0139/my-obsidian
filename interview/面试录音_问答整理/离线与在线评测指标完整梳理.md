# 离线评测指标和在线评测指标完整梳理

> 用途：统一AI Agent、RAG、Text-to-SQL系统的评测指标口径，避免面试中指标定义和计算方式不一致。
> 基于业界标准实践，结合项目实际数据，形成完整的评测指标体系。

## 一、总原则

所有评测指标回答都按同一个逻辑讲：

1. **先说定义**：这个指标是什么、怎么计算；
2. **再说数值**：给出当前数值或目标值；
3. **补充解释**：这个指标的意义和价值；
4. **主动讲边界**：指标的局限性和适用场景；
5. **给出下一步**：如何持续优化。

不要孤立抛数字。例如不要只说"准确率80%"，要说"RAG检索准确率@5是80%，这表示我们取前5个文档时有80%包含相关内容，但要注意这个指标不评估生成答案的质量，还需要结合相关性得分和用户采纳率综合判断"。

## 二、离线评测指标（Offline Evaluation Metrics）

### 1. AI Agent离线评测指标

#### 1.1 策略规划/推理能力指标

| 指标名称              | 计算方式                | 项目数值     | 解释与口径                        |
| ----------------- | ------------------- | -------- | ---------------------------- |
| **规划任务完成率**       | 成功完成任务数 / 总任务数      | 85%+     | 在Golden Set上测试，复杂归因任务的成功规划比例 |
| **推理步骤合理性**       | 专家评估推理步骤得分 / 总评估次数  | 4.2/5分   | 专家评分制，评估推理逻辑的合理性和完整性         |
| **计划执行效率**        | 任务完成所需步骤数 / 最少理论步骤数 | 1.2-1.5倍 | 衡量Agent是否会生成过多冗余步骤           |
| **DAG结构正确率**      | 结构合法的DAG数 / 总DAG数   | 99%      | 计算DAG的JSON格式合法性，非业务正确性       |
| **checkpoint命中率** | 成功命中关键节点数 / 总节点数    | 75%+     | 衡量Agent是否能按预期执行关键诊断步骤        |

**完整回答示例**：
> 我们的规划任务完成率在Golden Set上达到85%以上，这表示85%的复杂归因任务都能成功完成规划。推理步骤合理性评分是4.2分（满分5分），专家认为大部分推理逻辑都比较合理。计划执行效率大约是理论最少步骤的1.2-1.5倍，说明Agent会生成少量必要的冗余步骤，但不会过度复杂化。

#### 1.2 工具使用能力指标

| **工具参数正确率** | 参数正确的工具调用 / 总工具调用 | 90%+ | 参数格式和内容正确的比例          |
| **工具组合有效性** | 有效工具组合数 / 总组合尝试数  | 80%+ | 多个工具协作完成任务的效率         |
| **无效工具调用数** | 无实际效果的工具调用 / 总调用数 | <5%  | 衡量Agent是否会调用不必要的工具    |
| **工具选择准确率** | 选择最优工具次数 / 总选择次数  | 85%+ | 在多个可用工具中选择最佳工具的能力     |

**完整回答示例**：
> 工具调用准确率达到95%以上，这表明我们的Agent在调用API时基本不会出现网络或基础错误。工具参数正确率是90%，偶尔会有参数类型不匹配的情况。特别地，无效工具调用控制在5%以内，这说明Agent不会盲目调用工具，有较强的判断能力。

### 2. RAG系统离线评测指标

#### 2.1 检索质量指标

| 指标名称                 | 计算方式           | 项目数值  | 解释与口径               |
| -------------------- | -------------- | ----- | ------------------- |
| **检索准确率@5**          | 相关文档数 / 5      | 80%+  | 取前5个文档时包含相关文档的比例    |
| **检索召回率@10**         | 相关文档数 / 所有相关文档 | 75%+  | 在前10个文档中召回所有相关文档的比例 |

**完整回答示例**：
> 我们的RAG检索准确率@5达到80%，这意味着我们取前5个文档时有80%包含了用户需要的答案。NDCG@10是0.78，这表明我们的排序算法能将更相关的文档放在前面。但EM只有60%，这说明完全匹配还有提升空间，需要优化生成策略。

| **答案完整度**                | 完整回答比例 / 总回答数   | 70%+ | 是否回答了问题的所有方面 |
| **引用完整率**                | 包含正确引用的比例       | 80%+ | 是否正确标注信息来源   |
| **幻觉率**                  | 包含未在检索内容中信息的比例  | <15% | 避免编造信息的能力    |

**完整回答示例**：
> 相关性得分达到85%，这表明我们的Agent基本能做到"基于检索内容生成答案"。答案准确率是75%，这是因为在知识查询场景中，有些需要专业判断的问题可能会有偏差。幻觉率控制在15%以内，说明我们有较好的事实约束机制。

## 三、在线评测指标（Online Evaluation Metrics）

| 指标名称           | 计算方式                   | 项目数值   | 解释与口径       |
| -------------- | ---------------------- | ------ | ----------- |

| **任务完成满意度**    | 用户对任务完成评分 / 评分次数       | 4.0/5分 | 对任务完成效果的满意度 |

**完整回答示例**：
> 我们的NPS是40，这属于较好的水平。用户满意度评分达到4.1分，用户反馈总体满意。特别地，推荐采纳率是70%，这说明我们的建议有较高的参考价值，但还有提升空间。

| **EM vs Faithfulness** | EM是完全匹配，Faithfulness是基于检索内容 | "EM是完全匹配参考答案，而Faithfulness确保答案不编造信息，我们更看重Faithfulness" |
| **Schema recall vs precision** | recall是召回率，precision是精确率 | "Schema recall 80%表示能找到80%的相关表，precision 70%表示找到的表中有70%是相关的，我们更看重recall" |
| **结构正确率 vs 业务采纳率** | 结构正确是技术指标，业务采纳是价值指标 | "DAG结构正确率99%表示格式正确，但业务采纳率70%表示真正有价值，这很正常" |

## 五、面试中推荐主动抛出的"指标包"

### 1. 评测体系概览包

> 我们的评测体系分为离线和在线两部分。离线看Golden Set上的技术指标，比如RAG检索准确率@5是80%，SQL语义准确率是80%，DAG结构正确率达到99%。在线看业务价值，采纳率大约70%，用户满意度4.1分，任务完成时间比达到3-5倍。这样既有技术验证，又有业务价值。

### 2. Agent能力指标包

> Agent的能力可以从几个维度看：工具使用准确率95%以上，记忆管理能让90%的上下文保持，RePlan成功率90%多。这说明我们的Agent在工具调用、记忆和错误恢复方面都有较好的表现。当然，我们也关注转人工率控制在20%以内，这是实际使用中重要的业务指标。

### 3. 效果对比指标包

> 相比人工，我们的Agent能带来3-5倍的时间提升，错误减少60%以上。这个数字背后是每个具体的场景：知识查询能减少查文档时间，数据查询能减少写SQL时间，复杂归因能减少找研发的时间。我们正在统计具体的节省时长，让这个数字更扎实。

### 4. 成本效益指标包

> 每次交互成本大约5-10美分，投资回报率2-3倍。这个ROI计算是基于节省的人力成本和提升的效率。随着使用规模扩大，单次成本还会下降，而业务价值会持续增加，长期看ROI会更高。

### 5. 持续优化指标包

> 我们建立了完整的指标体系，包括技术指标和业务指标。每周会分析线上数据，哪些指标在下降，哪些场景bad case多。比如最近发现多跳问题准确率有所下降，我们就增加了few-shot示例，优化了检索策略。这样能确保指标持续提升。

## 六、注意事项

1. **不要混淆离线和在线指标**：离线指标是Golden Set上的测试结果，在线指标是真实用户使用的数据，两者可能不同。

2. **避免单一指标论**：不要只看准确率，要综合看采纳率、满意度、效率等多维度指标。

3. **口径要统一**：不同面试中要保持一致的指标定义和计算方式。

4. **主动解释指标局限性**：比如准确率高不代表用户一定满意，还要考虑易用性等因素。

5. **给出改进计划**：针对短板指标，要说明具体的改进方向。
