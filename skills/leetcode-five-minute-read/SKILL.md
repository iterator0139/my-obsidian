# 五分钟读题法 · 题解 Skill

## 何时使用

- 用户给出一道算法题，要求分析 / 做题解 / 写笔记
- 用户提到「五分钟读题法」「破局眼」「按我的模板」
- 在 Obsidian vault 的 `leetcode/` 目录下新建或补充题解

## 核心原则

1. **破局第一步不是想算法，而是分析题目性质**——识别信号 → 什么性质 → 什么方法 → 什么约束（见 [property-algorithm-mapping.md](property-algorithm-mapping.md)、[decision-trees.md](decision-trees.md)）
2. **输出服务于记忆**：一句话破局眼 > 长篇推导；性质表格 + 判断流程是可复用的记忆锚点
3. **先分类再细节**：大类定对，解法呼之欲出
4. **默认落盘**：分析完成后写入 Obsidian 笔记，不只留在聊天里

## 落盘步骤（默认执行）

用户给出题目要求分析 / 做题解时，**完成四步分析后必须写入文件**（用户明确说「只要聊天分析、不写笔记」时可跳过）。

### 文件路径

```
leetcode/{题号}. {题名}.md
```

示例：`leetcode/1047. 删除字符串中的所有相邻重复项.md`

### 文件结构

1. **题干**（文件最上方）：完整 LeetCode 题目描述——题面、示例、提示约束，与官网一致，不省略
2. **分隔线**：`---`
3. **题解**：`## 五分钟读题法分析` 及四步内容（见下方输出模板）

### 写入规则

- **新建**：按「题干 + `---` + 题解」完整创建
- **已存在**：保留原题干，在 `---` 之后补充或更新题解；不覆盖题干，除非用户要求
- **聊天回复**：仍给出破局眼摘要；完整内容以笔记文件为准

## 分析流程（严格按序）

### 第一步：分析性质（≈1 分钟，定大类）

**这是破局的第一步**：从题干提取性质，对照决策树定算法大类，再谈具体实现。不要跳过。

必须输出以下四块（不要跳过）：

#### 识别信号

用一句话回答：**题干里什么特点让我想到这个算法？** 对照 [property-algorithm-mapping.md](property-algorithm-mapping.md) 中对应算法的「识别信号」。

格式：

> **{识别信号，一句话}**

#### 题目性质

从题干提取 3–5 个关键性质标签，常见维度：

| 维度 | 问什么 |
|------|--------|
| **数据规模** | n 多大？决定暴力能不能过 |
| **数据结构** | 数组 / 字符串 / 链表 / 树 / 图？ |
| **目标类型** | 最值 / 计数 / 可行性 / 构造 / 模拟？ |
| **范围约束** | 连续子数组/子串？相邻？有序？ |
| **操作特征** | 增删改查？局部消除？配对？ |
| **单调性** | 扩窗/缩窗时条件是否单调？ |

#### 性质 → 方法

用表格写清「什么性质用什么方法」，并给出**反例**（不满足时换什么）：

| 性质 | 本题体现 | 若不满足则… |
|------|---------|------------|
| … | … | … |

附 **判断流程**（决策树式，从 [decision-trees.md](decision-trees.md) 选取或裁剪）：

```
题目是否 …？
  ├── 是 → ✅ 方法 A
  └── 否 → 方法 B / 不适用
```

#### 方法约束

写明选定方法**成立需要满足的条件**，以及本题是否满足：

- **约束**：方法 X 生效需要 …（通用条件，见 property-algorithm-mapping）
- **本题**：满足 / 不满足 + 一句说明
- **易混淆**：最容易套错的方法及原因

### 第二步：读题与盲猜（≈1 分钟）

在第一步定好的大类下，输出以下字段（不要跳过）：

- **题目核心**：一句话说清求什么
- **第一直觉**：最先想到的做法（哪怕会超时）
- **盲猜优化方向**：数据结构 + 目标时间复杂度 + 关键洞察（若有）

若盲猜与第一步结论冲突，必须解释为什么——通常说明性质分析有误。

### 第三步：最优解法

必须包含：

#### 核心转换（若有）

把题目等价变换成更熟悉的模型（例：0→-1，和为 0 的最长子数组）。

#### 状态定义

明确定义 DP 状态、前缀和、窗口含义等。

#### 核心状态转移（破局眼）

用公式或伪代码写出**最关键的一行逻辑**——这是整道题的记忆锚点。

#### 关键实现细节

- 初始化为什么这样写（如 `prefix_map = {0: -1}`）
- 为什么只存首次索引 / 为什么单调队列维护 max/min
- 常见陷阱（重复值、边界、空数组）

附 **Python 核心代码**（简洁、可运行），不要用过度封装的写法。

### 第四步：拆解记忆点

#### 一句话破局眼

格式固定：

> **LeetCode {题号} {题名}：{核心技巧，一句话}**

#### 复杂度对比

| 方法 | 时间 | 空间 | 适用性 |
|------|------|------|--------|

#### 关键理解点

编号列出 2–4 个「为什么」，针对最容易忘或最容易错的点。

#### 相关题目（可选）

列出同模式的题，Obsidian 链接格式：`[[leetcode/题号. 题名.md]]`

#### 滚动复习（可选）

一行浓缩，方便睡前过电影：

> **[[题号. 题名]]：{破局眼关键词}**

## 禁止事项

- 不要只做聊天分析不落盘——除非用户明确只要快速讨论
- 不要省略题干只写题解——笔记必须包含完整题目描述
- 不要跳过「分析性质」直接盲猜或给最优解——性质定大类，约束防套错模板
- 不要省略「识别信号」——必须写清「题干什么特点让我想到这个算法」
- 不要省略「性质 → 方法」表格和判断流程——这是用户最关注的可复用内容
- 不要跳过「盲猜」——盲猜是在已定大类下的直觉验证
- 不要把破局眼埋在长段落里——必须单独一行 `>` 引用块
- 不要给多种等价解法堆砌——只保留最优解 + 一句「面试可提的变体」（若有）
- 不要省略复杂度分析
