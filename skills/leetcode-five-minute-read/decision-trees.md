# 解题框架速查（分析性质 · 读题 1 分钟内快速判断）

> 用于「五分钟读题法」**第一步：分析性质**。从题干提取性质 → 走决策树定大类 → 核对方法约束。
> 完整流程见 [[SKILL.md]]。
>
> **深入理解「为什么想到这个算法」** → [[property-algorithm-mapping.md]]（识别信号 + 成立约束 + 易混淆）

## 性质提取清单（先扫一遍题干）

| 维度 | 典型问法 | 影响 |
|------|---------|------|
| 数据规模 | n ≤ ? | 暴力 / O(n) / O(n log n) |
| 连续 vs 不连续 | 子数组还是子序列？ | 滑动窗口 vs DP |
| 有序性 | 原数组有序？排序后有用？ | 双指针 / 二分 |
| 目标类型 | 最值 / 计数 / 可行性 / 模拟？ | DP / 哈希 / 直接模拟 |
| 局部 vs 全局 | 只看相邻？只看栈顶？ | 栈 / 贪心 |
| 单调性 | 扩窗条件是否单调？ | 滑动窗口能否用 |

---

## 1. 滑动窗口 → 单调队列 / 双指针

```
问题是否求连续子数组/子串？
  ├── 否 → 不用滑动窗口
  └── 是 → 约束条件是否关于窗口的"统计量"（max/min/sum/unique count）？
        ├── 否 → 不用
        └── 是 → 窗口移动时统计量能 O(1) 维护？
              ├── 否 → 考虑有序容器 O(n log n)
              └── 是 → ✅ 滑动窗口 + 单调队列 / 双指针
```

**窗口单调性条件**（必满足）：窗口越大条件越难满足（或越容易），扩窗变差缩窗变好。

| 约束类型 | 数据结构 | 代表题 |
|---------|---------|-------|
| `max - min ≤ limit` | 两个 deque | LC 1438 |
| 窗口 max | 一个 deque（单调递减） | LC 239 |
| 和/积 ≤ target | 双指针 | LC 209 |
| 窗口内字符覆盖 | 哈希表 + 双指针 | LC 76 |

## 2. 子数组/子序列 → 动态规划

```
求最值/方案数/可行性？
  ├── 子数组（连续）→ 一维 DP / Kadane
  ├── 子序列（不连续）→ 二维 DP
  └── 两个序列/字符串 → 二维 DP（LCS / 编辑距离）
```

## 3. 栈模拟 / 单调栈

### 3a. 配对消除、括号匹配、相邻操作 → 普通栈

```
操作只涉及「当前元素」与「已处理序列末尾」？
  ├── 相邻相同消除 / 括号匹配 / 逆序入栈正序出 → ✅ 普通栈模拟
  └── 需要找左右第一个更大/更小 → 见 3b 单调栈
```

| 性质 | 方法 | 约束 | 代表题 |
|------|------|------|--------|
| 只看相邻配对 | 栈顶比较 | 消除后连锁由栈自然处理 | LC 1047 |
| 括号嵌套 | 栈 | 左开右闭 | LC 20 |
| 逆序收集正序输出 | 栈 | — | LC 394 |

### 3b. 下一个更大/更小元素 → 单调栈

```
求每个元素右侧/左侧第一个比它大/小的元素？
  ├── 求更大 → 单调递减栈（遇到更大的结算）
  └── 求更小 → 单调递增栈（遇到更小的结算）
```

## 4. Top K / 第 K 大 → 堆 / 快速选择

```
求前 K 大/小 或 第 K 大/小？
  ├── 数据量大 → 堆 O(n log k)
  └── 数据量小 → 排序 O(n log n)
```

## 5. 两数/三数/四数之和 → 双指针 / 哈希表

```
求特定和的组合？
  ├── 无序数组 → 哈希表
  ├── 有序数组 → 双指针
  └── 多个数 → 固定一个 + 双指针
```

## 6. 数组有序 / 排序相关

```
数组是否有序？
  ├── 已排序 → 二分查找 / 双指针
  ├── 部分有序（旋转） → 变种二分
  └── 未排序 → 看数据范围决定暴力/哈希/排序
```

## 7. 小数据量 → 暴力

```
数据范围：
  ├── n ≤ 20    → 回溯 / 状态压缩
  ├── n ≤ 100   → O(n³) 暴力
  ├── n ≤ 1000  → O(n²) 双循环
  ├── n ≤ 10^5  → O(n log n) 排序/二分
  └── n ≤ 10^6  → O(n) 贪心/哈希/滑动窗口
```

> **破局第一步不是想算法，而是根据题目特征快速定位到上述某一大类。大类定对了，细节解法呼之欲出。**
