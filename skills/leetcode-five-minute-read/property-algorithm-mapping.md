# 性质与算法映射（深入版）

> 决策树告诉你「走哪条路」；本文告诉你 **看到什么性质会联想到什么算法、为什么有效、什么时候不能用**。
> 分析题目时，第一步先找 **识别信号**，再核对 **成立约束**。

## 怎么用

读题后问自己三句话：

1. **题干里有没有某个算法的识别信号？**（下面每节加粗的那句）
2. **该算法成立需要哪些约束？本题满足吗？**
3. **最容易误套成什么？**（每节「易混淆」）

---

## 栈（普通栈）

### 识别信号

> **新元素只需要和「已经处理完的结果」的最后一个元素发生关系。**

更具体地说，出现以下任一特点就该想到栈：

| 信号 | 题干关键词 / 场景 | 为什么想到栈 |
|------|------------------|-------------|
| **相邻配对** | 删相邻相同、合并相邻 | 消一对后左右拼接，只需知道「当前保留串末尾」 |
| **嵌套结构** | 括号、HTML 标签、嵌套文件夹 | 后开的先关，LIFO |
| **逆序依赖** | 先遇到外层、后处理内层 | 栈暂存「还没轮到处理」的部分 |
| **可撤销** | 操作有对称的 undo | 栈记录历史，pop = 撤销 |

### 为什么有效

栈维护的是 **「到目前为止、还不能确定最终去留」的后缀**。

- 1047：新字符只和栈顶比，相同就 pop（消一对），不同就 push——等价于模拟消除后的当前串
- 20 有效括号：遇到左括号 push，遇到右括号必须立刻和栈顶左括号匹配
- 394 字符串解码：遇到 `[` push 当前串和倍数，遇到 `]` pop 回来拼接

**本质**：信息只从「末尾」流入/流出，中间部分已经定型，不会再被当前元素影响。

### 成立约束

- ✅ 当前决策 **只依赖** 已处理序列的 **栈顶**（或最近几个）
- ✅ 处理顺序是 **线性扫描**，不需要回头改很久以前的位置
- ❌ 需要和 **任意远** 的元素配对 → 哈希表 / 双指针 / 二分
- ❌ 需要知道 **全局第 k 大** → 堆 / 排序

### 代表题

LC 1047、20、155、394、71（简化路径）

### 易混淆

| 误判 | 实际区别 |
|------|---------|
| 「删回文」→ 中心扩展 | 1047 只删 **相邻** 相同对，不是任意回文子串 |
| 「找左右边界」→ 普通栈 | 找 **第一个更大/更小** 是 **单调栈**（见下） |
| 「子序列」→ 栈 | 子序列不连续，栈管的是 **相邻/嵌套** 关系 |

## 单调栈

### 识别信号

> **每个元素都要找「左边/右边第一个比自己大（或小）的元素」。**

| 信号 | 场景 |
|------|------|
| **下一个更大/更小元素** | Next Greater Element |
| **以某柱子为高的矩形面积** | 左右第一个更矮的柱子定宽度 |
| **温度/股价等待天数** | 后面第一个更高温/更高价 |

### 为什么有效

维护一个 **单调** 的候选栈：不可能成为答案的元素会被提前弹出。

- 求「下一个更大」→ 维护 **递减栈**（栈底到栈顶递减）
- 当前元素比栈顶大 → 栈顶元素的「下一个更大」就是当前元素，弹出结算
- 剩下的元素「等着」后面更大的来结算

**本质**：每个元素最多入栈出栈一次，O(n) 完成 n 次「找邻居」。

### 成立约束

- ✅ 问的是 **第一个** 满足条件的邻居（距离最近）
- ✅ 比较关系是 **全序** 的（大小可比）
- ❌ 问的是 **所有** 配对组合 → 双指针 / 枚举
- ❌ 比较关系复杂（绝对值差等）→ 可能没有单调性

### 代表题

LC 496、739、84、42（解法之一）

### 易混淆

| 误判 | 实际区别 |
|------|---------|
| 普通栈 | 单调栈额外要求 **弹出时结算答案** |
| 双指针 | 双指针处理 **有序数组上的和目标**；单调栈处理 **位置关系** |

## 双指针

双指针不是一种算法，是 **利用单调性减少搜索空间** 的手势。分三种形态：

### A. 对撞指针（左右夹逼）

#### 识别信号

> **数组有序（或可排序），移动左指针会让答案变大，移动右指针会让答案变小（或反之）。**

| 信号 | 场景 |
|------|------|
| 有序数组找两数之和 | 16 三数之和 |
| 盛水、三角形容器 | 面积由短板决定，移动短板才可能变大 |
| 回文判断 | 两头比较 |

#### 为什么有效

有序性给了 **方向感**：知道该移哪边才能逼近目标，不会漏解。

```
和太小 → 左指针右移（变大）
和太大 → 右指针左移（变小）
```

#### 成立约束

- ✅ 存在 **单调方向**：移一边只会让度量单调变化
- ❌ 移左移右 **都可能** 让答案变好或变坏 → 无法夹逼，要 DP / 枚举

### B. 同向双指针（快慢 / 读写）

#### 识别信号

> **两个指针同方向扫描，快指针探索、慢指针维护有效区。**

| 信号 | 场景 |
|------|------|
| 原地删除 / 去重 | 27、26 |
| 合并两个有序数组/链表 | 21、88 |
| 链表找环 / 中点 | 141、876（快慢指针） |

#### 为什么有效

慢指针标记「已确认的输出位置」，快指针负责遍历，避免额外数组。

### C. 滑动窗口（同向双指针的特例）

#### 识别信号

> **求连续子数组/子串，且窗口扩大时某统计量单调变差（或变好）。**

见 [[decision-trees.md#1-滑动窗口--单调队列--双指针]]。

#### 易混淆（双指针全家）

| 场景 | 该用哪种 |
|------|---------|
| 有序数组 + 和目标 | 对撞 |
| 连续子串 + 约束统计 | 滑动窗口 |
| 原地修改数组 | 同向读写 |
| 无顺序约束的三元组枚举 | **不是** 双指针，是暴力/哈希 |

---

## 滑动窗口 + 单调队列

### 识别信号

> **连续子数组 + 约束涉及窗口内的 max/min，且窗口滑动时要在 O(1) 更新。**

普通滑动窗口用哈希表维护「种类数」；涉及 **最值** 时，暴力扫窗口是 O(k)，需要单调队列把「可能成为窗口 max 的候选」压在 deque 里。

### 成立约束

- ✅ 窗口有 **单调性**（扩窗变差则缩窗变好）
- ✅ max/min 查询要 **均摊 O(1)**
- ❌ 子序列（不连续）→ 不能滑窗

## 动态规划

### 识别信号

> **当前选择会影响未来，且子问题重叠——需要记住子问题的最优解。**

| 信号 | 场景 |
|------|------|
| 求最值/方案数 | 最大子数组和、爬楼梯 |
| 两个序列比较 | LCS、编辑距离 |
| 选或不选 | 0-1 背包、打家劫舍 |
| 划分/分割 | 单词拆分、回文分割 |

### 为什么有效

最优子结构：大问题的最优解包含小问题的最优解。记忆化避免重复计算。

### 成立约束

- ✅ 能定义清晰的 **状态** 和 **转移**
- ✅ 无后效性：当前状态概括了所有历史信息
- ❌ 贪心能证 → 不必 DP
- ❌ 只需可行性/模拟 → 可能不需要 DP

### 易混淆

| 误判 | 实际区别 |
|------|---------|
| 连续子数组最值 | 一维 DP / Kadane，不是二维 |
| 「回文」 | 最长回文 **子串** 可中心扩展 O(n²)；**子序列** 才二维 DP |

## 哈希表

### 识别信号

> **需要 O(1) 回答「之前有没有出现过 X」「X 出现了几次」「X 的 complement 在哪」。**

| 信号 | 场景 |
|------|------|
| 两数之和（无序） | complement = target - num |
| 频次统计 | 字母异位词、多数元素 |
| 前缀和 + 首次索引 | 560 和为 K 的子数组 |

### 成立约束

- ✅ 查询/更新均摊 O(1)
- ❌ 需要 **有序** 信息做夹逼 → 排序 + 双指针可能更省空间
- ❌ 需要 **第 K 大** → 堆

---

## 二分查找

### 识别信号

> **答案或位置具有单调性：满足条件的排在一起，可以判断 mid 然后丢弃一半。**

两种形态：

| 形态 | 信号 |
|------|------|
| 有序数组找值 | 33 搜索旋转数组 |
| 答案二分 | 最小化最大值、最大化最小值（对 **答案空间** 二分） |

### 成立约束

- ✅ 存在 predicate `P(x)`：false…false, true…true（或反过来）
- ❌ 没有单调性 → 不能二分

## 堆

### 识别信号

> **只关心当前最大/最小的若干个，不需要全局有序。**

| 信号 | 场景 |
|------|------|
| Top K | 215 第 K 大 |
| 多路归并 | 23 合并 K 个链表 |
| 数据流中位数 | 双堆 |

### 成立约束

- ✅ 只需维护 **部分有序**
- ❌ 需要 **完整排序** 或 **双指针夹逼** → 排序可能更简单

---

## 贪心

### 识别信号

> **局部最优能推出全局最优，且选择不会阻塞更好的未来选择。**

| 信号 | 场景 |
|------|------|
| 区间调度 | 无重叠区间最大数 |
| 分配问题 | 分饼干、柠檬水找零 |
| 排序后相邻比较 | 435 无重叠区间 |

### 成立约束

- ✅ 能证明 **交换论证** 或 **贪心选择性质**
- ❌ 局部最优会埋坑 → 必须 DP

## 快速对照：看到这些词先想谁

| 题干感受 | 第一反应 | 第二反应 |
|---------|---------|---------|
| 「相邻」「配对」「嵌套」「撤销」 | **栈** | 是找更大邻居？→ 单调栈 |
| 「有序」「两头」「和太大/太小」 | **对撞双指针** | 能排序吗？ |
| 「连续子串/子数组」「最长/最短满足条件」 | **滑动窗口** | 涉及窗口 max/min？→ 单调队列 |
| 「之前见过吗」「频次」「补数」 | **哈希** | 有序？→ 双指针 |
| 「最值」「多少种方案」「选或不选」 | **DP** | 贪心能证吗？ |
| 「第 K 大」「只要最大的几个」 | **堆** | n 小？→ 排序 |
| 「最小化最大值」 | **二分答案** | 验证函数怎么写？ |
| 「n ≤ 100」 | **暴力** | 别过度优化 |

## 写进题解的格式（第一步：分析性质）

每道题在「性质 → 方法」表里，除了填性质，还要写 **识别信号** 一行：

```markdown
#### 识别信号
> **{用一句话说：题干里什么特点让我想到这个方法}**

#### 性质 → 方法
| 性质 | 本题体现 | 若不满足则… |
| … | … | … |

#### 方法约束
- **约束**：{该算法通用的成立条件}
- **本题**：满足 / 不满足
- **易混淆**：{最容易误套的方法}
```

范例见 [[leetcode/1047. 删除字符串中的所有相邻重复项.md]]。
