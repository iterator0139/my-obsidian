# 方法详解、公式与选型指南

本文是 [[01-演进脉络]] 的技术补充：逐个说明主流指标的**原理、公式、实现陷阱、适用与禁用场景**，并给出可直接落地的选型与评估工程规范。

---

## 1. 指标分类学

任何生成评估方法都可以用三个正交维度定位，混用会在报告里产生歧义：

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 是否需要参考 | 全参考（FR）/ 无参考（NR）/ 分布参考 | "无参考"不代表无信息，而是用模型（CLIP/VLM）或先验替代真值 |
| 评估粒度 | 分布级 / 样本级 | 分布级（FID）测"整体像不像真实数据"；样本级（CLIPScore）测"这一条输出好不好" |
| 打分主体 | 数学指标 / 预训练模型 / 人类 | 三者能力上限依次升高，成本与可复现性依次下降 |

一句话判据：**分布级指标排序模型整体水平，样本级指标定位具体缺陷，人类评估裁决产品可用性**。

## 2. 图像生成评估方法详解

### 2.1 分布级指标

#### FID（Fréchet Inception Distance）

把真实图与生成图分别过 Inception-v3（ImageNet 预训练），取池化层特征，各自拟合高斯分布，度量两个高斯的 Fréchet 距离：

```
FID = ||μ_r − μ_g||² + Tr(Σ_r + Σ_g − 2·(Σ_r Σ_g)^{1/2})
```

- **它真正衡量的是**：在 ImageNet 语义特征空间里的分布重叠程度（既是质量也是多样性的混合体）。
- **实现陷阱（决定结论是否可信）**：
  - 图像缩放算法：不同 resize（PIL bilinear vs. antialias）可让同一模型的 FID 相差数个百分点 → 用 `clean-fid`（arXiv:2104.11222）的预处理；
  - 样本量：10k 以下噪声极大，需要报告样本数与置信区间（无偏估计见 CVPR 2020 *Effectively Unbiased FID and IS*）；
  - 特征权重与层号必须固定（旧实现用 `pool3`，新实现用 `pool_3`/2048 维，混用即不可比）；
  - 真实分布与生成分布样本数需对齐。
- **何时不该用**：编辑任务（输出与输入高度相关）、需要"计数/空间关系"判断、需要单张图诊断、以及任何"生成分布与 ImageNet 分布差异极大"的场景（如医学、遥感、工业缺陷）。

#### 其他分布指标

| 指标 | 公式核心 | 相对 FID 的优势 | 代价 |
| --- | --- | --- | --- |
| KID（arXiv:1801.01401） | 多项式核 MMD²（无偏估计） | 无高斯假设、小样本更稳 | 数值不直观，报告惯例弱 |
| CMMD（arXiv:2401.09603） | CLIP 嵌入上的 RBF-kernel MMD | 与人偏好相关性优于 FID；无需 Inception | 依赖 CLIP 的语义空间 |
| MIND（Monge Inception Distance, arXiv:2605.06797） | 最优传输替代 Fréchet | 对非高斯分布更稳健（2026 新出） | 生态尚未铺开 |
| Precision / Recall（arXiv:1806.00035、1904.06991） | 流形交并估计 | 显式解耦质量与多样性 | 超参敏感 |
| Density / Coverage（arXiv:2002.09797） | 基于 k-NN 流形体积 | 修正 P/R 对离群点的失效 | 计算量大 |
| RA-ClipScore（arXiv:2608.12088） | 可解释性改造的 CLIPScore | 可诊断"哪里不匹配" | 2026 新出，采用度待观察 |

> 2026 年的明确信号：*What FID Hides*（arXiv:2608.24881）系统展示了 FID 相同的两个模型在偏差结构上可以完全不同——**FID 相等不代表能力相同**，报告应至少附一个诊断型指标。

### 2.2 低层保真与感知指标

| 指标 | 公式/原理 | 今天还在哪用 | 常见误用 |
| --- | --- | --- | --- |
| PSNR/MS-SSIM | 像素误差 / 结构相似度的多尺度版本 | 超分、复原、编解码 | 用来排序生成模型（与感知脱节） |
| LPIPS（arXiv:1801.03924） | `Σ_l w_l · ‖φ_l(x) − φ_l(y)‖²`，φ 为预训练 CNN 特征，w 为学习权重 | 编辑任务"改动幅度"、超分、帧间一致性 | 用无参考生成任务、跨域（医学/线条画）时权重失效 |
| DISTS（arXiv:2004.07728） | 结构与纹理双分支的感知距离 | 纹理型失真更稳的替代 | 同上 |
| NIMA / MUSIQ（arXiv:1709.05424 / 2108.05997） | 直接回归人类评分（分布 / 多尺度 Transformer） | 美学打分、无参考质量 | 训练域外泛化差（拿自然图模型评渲染图） |

### 2.3 语义对齐与组合性

| 方法 | 打分机制 | 能测 | 测不了 |
| --- | --- | --- | --- |
| CLIPScore（arXiv:2104.08718） | `max(100·cos(f_img, g_text), 0)` | 粗粒度语义相关 | 计数、否定、空间关系、属性绑定 |
| TIFA（arXiv:2303.11897） | 生成 QA 对后答题 | 细粒度元素出现 | 需要好的问题生成器 |
| DSG（Davidsonian Scene Graph 系列） | 把提示拆成原子命题逐条验证 | 关系型命题 | 流水线复杂、误差累积 |
| VQAScore（arXiv:2404.01291） | 计算 VLM 输出 "Yes" 的概率 | 组合性、关系、长提示 | 受措辞与 VLM 能力影响 |
| GenEval / DPG-Bench / T2I-CompBench（arXiv:2310.11513 / 2403.05135 / 2307.06350） | 用检测器/分割/VQA 做结构化判定 | 计数、颜色、位置、属性绑定 | 检测器能力上限；提示集有限且可能过时 |

**选用建议**：

- 只跟踪趋势 → CLIPScore（便宜、可比、别对绝对值做结论）。
- 论文对标 → GenEval + T2I-CompBench++ + DPG-Bench 三件套（社区认可度最高）。
- 产品回归 → VQAScore 或自建 VQA 式检查项（可用自有业务提示词，避免公开提示集污染）。
- **任何语义指标都必须报告底座模型版本**（CLIP/VLM 换版本等于换指标）。

### 2.4 人类偏好代理（reward model）

| 模型 | 训练数据量级 | 特点 | 使用注意 |
| --- | --- | --- | --- |
| ImageReward（arXiv:2304.05977） | 十万级人类比较 | 早期标准，广泛用于微调 | 数据集偏工程美学 |
| HPS v2（arXiv:2306.09341） | 近百万级比较 | 榜单常用；HPSv3（arXiv:2508.03789）、HPSv3++（arXiv:2606.14657）持续扩展 | 版本间分数不可比 |
| PickScore（arXiv:2305.01569） | 五十万级真实点击 | 反映真实用户行为 | 平台人群偏差 |
| VisionReward / UnifiedReward（arXiv:2412.21059 / 2503.05236） | 多源 | 图 + 视频统一、多维输出 | 多维分数需要聚合策略 |
| DiT-Reward / RubricRM（arXiv:2606.23626 / 2608.26956） | 2026 新 | 用生成模型自身表征 / 动态 rubric | 处于快速迭代期 |

**纪律性要求**：

1. 至少用两个偏好模型，且报告两者分歧（分歧本身就是结论）。
2. 偏好模型只用于**筛选与排序**；最终结论必须有人类评估抽检校准。
3. 一旦把偏好模型当训练奖励，必须监控 pattern collapse 与攻击面（*BadReward*，arXiv:2506.03234）。

### 2.5 编辑、个性化与可控性

| 任务 | 评估要点 | 代表工作 |
| --- | --- | --- |
| 指令编辑 | "该改的改了 + 不该改的没动"，需要同时测对齐与保真 | EditBench（arXiv:2212.06909）、ReasonEdit（arXiv:2605.07477）、MIEScore（arXiv:2608.02059）、LMM4Edit（arXiv:2507.16193）、编辑综述（arXiv:2607.25642） |
| 主体个性化 | 身份保持 + 可交互性 | DreamBench 系列（社区标准） |
| 空间/局部语义控制 | 局部语义可控性 | T2LSC-Bench（arXiv:2609.02255） |
| 多源编辑 | 多参考输入的一致性 | MIEScore、Evaluation-Verification Reward（arXiv:2607.29025） |
| 时间/因果想象 | 单图能否推演未来状态 | ImageTime（arXiv:2606.10620） |
| 推理驱动生成 | 生成需要推理步骤 | Thinking in Pictures（arXiv:2609.02864） |
| 物理编辑 | 编辑后的物理合理性 | PhyEditBench（ECCV 2026） |

编辑任务的通用做法：**双指标对**——一项测"改动是否发生"（VQA/CLIP 对齐），一项测"未编辑区域是否保持"（LPIPS/DISTS 掩码内外的对比）。

## 3. 视频生成评估方法详解

### 3.1 时空保真与运动指标

| 指标 | 原理 | 状态 |
| --- | --- | --- |
| FVD（arXiv:1812.01717） | I3D 特征 + Fréchet 距离 | 已降级为辅助；跨论文不可比（数据集小、方差大） |
| ISV（Inception Score Video） | 帧级 IS 的时序版本 | 基本退出使用 |
| Warping error / 光流一致性 | 用光流把前一帧 warp 到当前帧比较 | 仍是"时序闪烁/一致性"最直接的度量，被 VBench 等间接使用 |
| 逐帧 LPIPS/SSIM 聚合 | 帧级指标 + 时序池化（均值/最差/加权） | 通用做法，池化方式必须报告 |

### 3.2 分解式基准：VBench 系

- **VBench（arXiv:2311.17982, CVPR 2024）**：数百条提示 + 16 个维度，分两大类——
  - 时序质量（7）：主体一致性、背景一致性、时序闪烁、运动平滑度、动态程度、美学质量、成像质量；
  - 语义（9）：物体类别、多物体、人体动作、颜色、空间关系、场景、外观风格、时序风格、整体一致性。
  最终按人为权重聚合为总分。
- **VBench++（arXiv:2411.13503）**：扩展 image-to-video 与更细的能力维度。
- **VBench-2.0（arXiv:2503.21755）**：转向"内在忠实性"，5 大维度（人像保真、可控性、创造力、物理、常识）共 18 个子维度——**标志着评估目标从"视觉观感"转向"是否理解世界"**。
- **使用注意**：总分权重是人为设定的，改权重可改排序；跨版本（VBench vs VBench-2.0）分数不可比；提示集公开且被大量用于模型调优，存在污染。

### 3.3 其他视频基准对比

| 基准 | 侧重 | 提示/规模 | 适合回答 |
| --- | --- | --- | --- |
| EvalCrafter（arXiv:2310.11440） | 18 指标 × 4 大类（视觉质量、内容、运动、文本对齐） | 700 提示 | "哪个模型综合更强" |
| FETV（arXiv:2311.01813） | 细粒度指令遵循 | 600+ 提示、多维度 | "它听不听得懂提示" |
| T2V-CompBench（arXiv:2407.14505） | 组合性（7 类） | 千条量级提示 | "多物体/属性/关系是否画对" |
| TC-Bench（arXiv:2406.08656） | 时序组合性（动作先后、状态变化） | 专门设计 | "因果与时序是否合理" |
| VideoScore（arXiv:2406.15252） | MLLM 模拟人类反馈打分 | 数万条人类标注 | "无需人力的细粒度打分" |
| ChronoMagic-Bench（arXiv:2406.18522） | 时间流逝/形态变化 | 专门提示 | "物理形态演化是否可信" |
| VideoPhy（arXiv:2406.03520） | 物理常识 | 专门提示 | "是否违反物理" |
| VGA-BenchV2（arXiv:2608.25452） | 美学 + 生成质量统一 | 2026 扩展版 | "观感维度的统一报告" |
| Sci-VBench（arXiv:2608.09873） | 科学领域知识与推理 | 2026 新 | "需要专业知识时是否答对" |

## 5. 评估工程规范（Checklist）

**提示集**

- 覆盖度分层：主体/属性/计数/空间关系/文字渲染/风格/文化元素/长提示/否定句。
- 难度分层并公开分层结果（只报平均分会掩盖短板）。
- 与训练数据隔离；定期检测污染（同提示同种子复现测试）。

**自动指标**

- 固定预处理、模型权重、样本数、随机种子；优先用被广泛审计的实现（`clean-fid`、`IQA-PyTorch`、`torchmetrics`）。
- 报告分布指标时给出**样本量与自助法置信区间**，样本量不足时不给小数位。
- 每个分数都注明"在什么数据分布上算的"（COCO vs 自有域，结论不可通用）。

**模型评委（MLLM/VLM judge）**

- 用 rubric（分项细则）而非单一整体分；每项给判定标准与反例。
- 交换候选顺序做位置偏差检验；控制输出长度对分数的影响。
- 抽 5%–10% 由人类复核，报告一致性（Krippendorff α / Spearman）。
- 严禁把未经校准的 judge 直接当 RL 奖励。

**人类评估**

- 明确协议：2AFC 并排 / MOS / Likert / Elo（Bradley-Terry 拟合）。
- 标注者招募与筛选标准、报酬、样本量、语言与文化覆盖。
- 报告标注者内/间一致性；不一致本身是重要结论。
- 统计学：预先注册方案、多重比较校正、效果量而非仅 p 值。

**报告规范**

- 公开代码、权重、提示集、采样参数、评测脚本与原始分数。
- 禁止 cherry-pick：同时展示随机抽样与最好样本。
- 成本核算：把评测的 GPU 小时与人力成本写进方法学（2026 年评审开始关注这一点）。

## 6. 常见误判案例（来自上述文献）

1. **FID 更低但人更不喜欢**：CMMD（arXiv:2401.09603）与后续诊断（arXiv:2608.24881）反复验证。
2. **FVD 更优但物理错误**：运动指标对"是否违反物理"完全无感（Physics-IQ 的核心论点）。
