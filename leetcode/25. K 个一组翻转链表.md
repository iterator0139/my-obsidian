给你链表的头节点 `head` ，每 `k` 个节点一组进行翻转，请你返回修改后的链表。

`k` 是一个正整数，它的值小于或等于链表的长度。如果节点总数不是 `k` 的整数倍，那么请将最后剩余的节点保持原有顺序。

你不能只是单纯的改变节点内部的值，而是需要实际进行节点交换。

**示例 1：**

![](https://assets.leetcode.com/uploads/2021/02/19/rev2ex2.jpg)

**输入：**head = [1,2,3,4,5], k = 2
**输出：**[2,1,4,3,5]

**示例 2：**

**输入：**head = [1,2,3,4,5], k = 3
**输出：**[3,2,1,4,5]

**提示：**

- 链表中的节点数目为 `n`
- `1 <= k <= n <= 5000`
- `0 <= Node.val <= 1000`

**进阶：**你可以设计一个只用 O(1) 额外内存空间的算法解决此问题吗？

## 五分钟读题法分析

### 第一步：分析性质

#### 识别信号

> **链表上的分段局部操作——每段做同一件事（反转），难点在段与段之间的指针拼接，不是反转本身。**

#### 题目性质

- **数据规模**：n ≤ 5000，O(n) 一趟足够
- **数据结构**：单向链表
- **目标类型**：构造（原地改指针，不能改值）
- **范围约束**：按固定长度 k 分段；不足 k 的尾部保持原序
- **操作特征**：重复子问题 = 「反转 k 个节点」+ 「接上已处理部分」

#### 性质 → 方法

| 性质 | 本题体现 | 若不满足则… |
|------|---------|------------|
| 链表指针操作 | 改 `next`，不改 `val` | 数组可直接切片反转 |
| 固定长度分段反转 | 每组恰好 k 个 | 只反转一段 [left,right] → LC 92 |
| 整段反转是子问题 | 每组 = 标准反转链表 | 只反转整条 → LC 206 |
| 头结点可能变 | 第一组反转后新头不同 | 用 dummy 哨兵简化 |
| 需先判断够不够 k 个 | 尾部不足 k 不动 | 不判断会访问空指针 |

**判断流程**：

```
链表上的反转题？
  ├── 反转整条？
  │     └── 是 → LC 206（迭代三指针 / 递归）
  ├── 反转区间 [left, right]？
  │     └── 是 → LC 92（头插法 / 断链反转）
  └── 每 k 个一组反转？
        ├── 是 → ✅ 206 做子过程 + dummy 管拼接
        └── 不足 k 尾部保留 → 先探测第 k 个是否存在
```

#### 方法约束

- **约束**：反转子链表需要记住「组前驱」和「组后继」，反转后把 `{组前驱 → 新头}`、`{新尾 → 组后继}` 接上
- **本题**：满足。每组独立反转，组间连接互不干扰
- **易混淆**：
  - 不是快慢指针题——不需要找中点/环
  - 不能先遍历数长度再按索引切——要 O(1) 额外空间时只能边扫边反转（进阶要求）

### 第二步：读题与盲猜

**题目核心**：每 k 个节点为一组原地反转；最后不足 k 的节点不动；返回新头。

**第一直觉**：把链表切成若干段，每段调用「反转链表」，再首尾相连。难点是切断/接回时指针别丢。

**盲猜优化方向**：

- **数据结构**：dummy 哨兵 + 几个游标（`prev` 组前驱、`kth` 组尾、`group_next` 组后继）
- **时间复杂度**：O(n)，每个节点指针改常数次
- **关键洞察**：先探测本组是否有 k 个节点；有则反转 `prev.next` 到 `kth` 这一段，再把 `prev` 移到新尾（原组头）处理下一组

---

### 第三步：最优解法

#### 核心转换

```
K 个一组翻转
  ⇔ 重复执行：「若后面还有 k 个节点 → 反转这 k 个 → 接到已处理链表后面」
  ⇔ 每组都是 LC 206，外加三段拼接
```

#### 状态定义（迭代）

| 变量 | 含义 |
|------|------|
| `dummy` | 哨兵，`dummy.next` 为答案头 |
| `prev` | **当前组的前驱**（上一组反转后的尾，或 dummy） |
| `kth` | 当前组第 k 个节点（反转前是组尾） |
| `group_next` | 当前组后继（下一组起点） |
| `prev_group` | 反转前组头（反转后变组尾） |

#### 核心状态转移（破局眼）

```
1. 从 prev 出发走 k 步找 kth；走不到 → 结束
2. group_next = kth.next
3. 反转 prev.next … kth（标准三指针，终止于 group_next）
4. prev.next = kth        # 新头接上
5. prev = prev_group      # 移到新尾，处理下一组
```

反转内层（与 LC 206 相同）：

```python
rev_prev, curr = group_next, prev.next
while curr != group_next:
    nxt = curr.next
    curr.next = rev_prev
    rev_prev, curr = curr, nxt
# rev_prev = 新头(kth), prev_group = 新尾
```

#### 关键实现细节

- **dummy 必不可少**：第一组反转后真实头结点变了，`dummy.next` 始终是答案入口
- **先探测再反转**：不足 k 个时直接 `return dummy.next`，避免反转残缺段
- **`prev` 更新为 `prev_group`（原组头）**：反转后原组头变组尾，是下一组的「前驱」
- **内层反转终止条件 `curr != group_next`**：用 `group_next` 作边界，不必真的断链
- **递归写法**（面试可提）：先检查 k 步 → 反转前 k 个 → `head(原组头,现尾).next = reverseKGroup(第k+1个, k)` → 返回新头

### 核心代码（Python · 迭代）

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


def reverseKGroup(head: ListNode, k: int) -> ListNode:
    dummy = ListNode(0, head)
    prev = dummy

    while True:
        kth = prev
        for _ in range(k):
            kth = kth.next
            if not kth:
                return dummy.next

        group_next = kth.next
        prev_group = prev.next

        # 反转 [prev.next, kth]
        rev_prev, curr = group_next, prev_group
        while curr != group_next:
            nxt = curr.next
            curr.next = rev_prev
            rev_prev, curr = curr, nxt

        prev.next = kth      # 新头
        prev = prev_group    # 新尾，下一组前驱

    return dummy.next
```

**递归变体**（逻辑更短，栈深 O(n/k)）：

```python
def reverseKGroup(head: ListNode, k: int) -> ListNode:
    curr = head
    for _ in range(k):
        if not curr:
            return head
        curr = curr.next

    prev, curr = None, head
    for _ in range(k):
        nxt = curr.next
        curr.next = prev
        prev, curr = curr, nxt

    head.next = reverseKGroup(curr, k)  # head 已是本组尾
    return prev
```

### 第四步：拆解记忆点

#### 一句话破局眼

> **LeetCode 25 K 个一组翻转链表：dummy + 先探测 k 步；每组套用 206 反转；`prev` 接新头、移到新尾，循环下一段。**

#### 复杂度对比

| 方法 | 时间 | 空间 | 适用性 |
|------|------|------|--------|
| 转数组反转再建树 | O(n) | O(n) | 不符合进阶 O(1) 空间 |
| 迭代 + dummy | O(n) | O(1) | ✅ 最优 |
| 递归 | O(n) | O(n/k) 栈 | 代码短，长链可能栈溢出 |

#### 关键理解点

1. **难的不是反转，是拼接**——每组反转后，必须同时接上「组前驱 → 新头」和「新尾 → 下一组」。
2. **为什么要先走 k 步？** 尾部不足 k 个时不能动；探测阶段发现 `kth` 为空就直接收工。
3. **`prev` 为什么指向新尾而不是新头？** 下一组需要的是「上一组最后一个节点」作为前驱，原组头反转后就是尾。
4. **与 LC 92 的关系**：92 是反转一个已知区间；25 是重复「定长区间反转」，且区间起点随 `prev` 滑动。
