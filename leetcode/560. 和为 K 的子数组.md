给你一个整数数组 `nums` 和一个整数 `k`，返回和为 `k` 的 **子数组** 的个数。

**子数组** 是数组中 **连续** 且 **非空** 的元素序列。

**示例 1：**

**输入：** nums = [1,1,1], k = 2
**输出：** 2

**示例 2：**

**输入：** nums = [1,2,3], k = 3
**输出：** 2

**提示：**

- `1 <= nums.length <= 2 * 10^4`
- `-1000 <= nums[i] <= 1000`
- `-10^7 <= k <= 10^7`

---

## 五分钟读题法分析

### 第一步：分析性质

#### 识别信号

> **连续子数组 + 和恰好等于 K → 前缀和差；用哈希表 O(1) 查「之前有没有前缀和 = 当前前缀和 - K」。**

#### 题目性质

- **数据规模**：n ≤ 2×10⁴，暴力 O(n²) 会 TLE
- **数据结构**：整数数组，元素可为负
- **目标类型**：计数（有多少个子数组和 = k）
- **范围约束**：必须是**连续**子数组（subarray ≠ subsequence）
- **操作特征**：和是**精确值** k，不是整除/取模

#### 性质 → 方法

| 性质 | 本题体现 | 若不满足则… |
|------|---------|------------|
| 连续子数组 + 和的条件 | 和恰好 = k | 非连续 → 子序列 / DP |
| 前缀和差表示子数组和 | sum(i+1,j) = prefix[j] - prefix[i] | 无「和」条件 → 滑动窗口（需单调） |
| 需要查历史前缀和 | 当前 prefix 要配对 prefix - k | 求最长 → 525 只存首次索引 |
| 元素可为负 | 窗口内和没有单调性 | 有非负 + 和 ≤ k → 可变滑动窗口 |

**判断流程**：

```
是否「连续子数组 + 和的条件」？
  ├── 是 → 前缀和 + 哈希表
  │     ├── 和恰好 = K？ → ✅ 560：查 prefix - K 的出现次数
  │     ├── 和 % K = 0？  → 974：查相同余数
  │     └── 0/1 相等？    → 525：0→-1，查相同前缀和 + 首次索引
  └── 否 → 其他方法
```

#### 方法约束

- **约束**：前缀和成立需要子数组**连续**；哈希表记录「某个前缀和出现过几次」
- **本题**：满足；有负数时滑动窗口不适用（窗口扩大/缩小时和可增可减，无单调性）
- **易混淆**：不要套滑动窗口——`[1, -1, 1]` 且 k=1 时，窗口和会来回跳；不要套 974 的取模——本题是精确相等

### 第二步：读题与盲猜

**题目核心**：统计有多少个连续子数组，元素之和恰好等于 k。

**第一直觉**：双重循环枚举所有 [i, j]，累加求和，O(n²)，n=2×10⁴ 会超时。

**盲猜优化方向**：

- **数据结构**：前缀和 + 哈希表（前缀和 → 出现次数）
- **时间复杂度**：O(n)
- **关键洞察**：若 `prefix[j] - prefix[i] = k`，则 `prefix[i] = prefix[j] - k`——每步只需查「之前有多少个前缀和等于 `当前前缀和 - k`」

---

### 第三步：最优解法

#### 核心转换

子数组 `nums[i+1..j]` 的和：

```
sum(i+1, j) = prefix[j] - prefix[i] = k
⟺  prefix[i] = prefix[j] - k
```

把「找区间和」变成「找历史前缀和」——哈希表的经典用法。

#### 状态定义

- `prefix`：从数组开头到当前位置的前缀和
- `count[s]`：遍历过程中，前缀和为 `s` 已出现的次数
- `ans`：满足条件的子数组总数

#### 核心状态转移（破局眼）

```
每步更新 prefix += nums[i]
ans += count.get(prefix - k, 0)   # 之前每个 prefix-k，都和当前位置配成一段和为 k 的子数组
count[prefix] = count.get(prefix, 0) + 1
```

#### 关键实现细节

- **初始化 `count[0] = 1`**：空前缀和为 0；处理「从数组开头就和为 k」的子数组（如 `nums=[3], k=3`）
- **先累加 ans 再更新 count**：不能把当前位置和自身配对
- **负数元素**：前缀和可正可负，哈希表 key 是任意整数，不影响正确性
- **和 974 的区别**：560 查 `prefix - k`（差等于 k）；974 查 `prefix % k`（余数相同）

### 核心代码（Python）

```python
def subarraySum(nums: list[int], k: int) -> int:
    count = {0: 1}
    prefix = 0
    ans = 0
    for x in nums:
        prefix += x
        ans += count.get(prefix - k, 0)
        count[prefix] = count.get(prefix, 0) + 1
    return ans
```

### 第四步：拆解记忆点

#### 一句话破局眼

> **LeetCode 560 和为 K 的子数组：前缀和 + 哈希表，每步查「prefix - k」出现了几次。**

#### 复杂度对比

| 方法 | 时间复杂度 | 空间复杂度 | 适用性 |
|------|-----------|-----------|--------|
| 暴力枚举子数组 | O(n²) | O(1) | n 小可用 |
| **前缀和 + 哈希** | **O(n)** | **O(n)** | **本题最优** |

#### 关键理解点

1. **为什么是 prefix - k？** 子数组和 = `prefix[j] - prefix[i]`，令其 = k，移项得 `prefix[i] = prefix[j] - k`
2. **为什么 count[0]=1？** 空前缀代表「从 index 0 开头」的子数组；没有它，`[3]` 且 k=3 会漏计
3. **为什么不用滑动窗口？** 有负数时窗口和没有单调性，扩/缩右指针无法保证正确
4. **560 vs 974 vs 525**：560 差等于 K 计数；974 余数相同计数；525 余数相同但只存首次索引求最长
