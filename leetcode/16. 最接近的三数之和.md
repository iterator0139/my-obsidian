给你一个长度为 `n` 的整数数组 `nums` 和 一个目标值 `target`。请你从 `nums` 中选出三个在 **不同下标位置** 的整数，使它们的和与 `target` 最接近。

返回这三个数的和。

假定每组输入只存在恰好一个解。

**示例 1：**

**输入：**nums = [-1,2,1,-4], target = 1
**输出：**2
**解释：**与 target 最接近的和是 2 (-1 + 2 + 1 = 2)。

**示例 2：**

**输入：**nums = [0,0,0], target = 1
**输出：**0
**解释：**与 target 最接近的和是 0（0 + 0 + 0 = 0）。

**提示：**

- `3 <= nums.length <= 1000`
- `-1000 <= nums[i] <= 1000`
- `-104 <= target <= 104`

## 五分钟读题法分析

### 第一步：分析性质

#### 识别信号

> **从 n 个数里选 k 个（本题 k=3）凑目标和，无序数组可先排序，固定一个数后剩下两数之和变成有序数组上的夹逼问题。**

#### 题目性质

- **数据规模**：n ≤ 1000，O(n³) 暴力可过，但排序 + 双指针 O(n²) 更优
- **数据结构**：无序整数数组
- **目标类型**：最值（与 target 的绝对差最小）
- **范围约束**：三个不同下标，元素可重排（顺序无关）
- **单调性**：排序后，左指针右移 → 和变大；右指针左移 → 和变小

#### 性质 → 方法

| 性质           | 本题体现         | 若不满足则…                          |
| ------------ | ------------ | ------------------------------- |
| 选 k 个数凑和     | k=3          | k=2 → 哈希 / 双指针；k=4 → 固定两个 + 双指针 |
| 无序但顺序无关      | 只要求和         | 有位置约束 → 不能先排序                   |
| 排序后双指针有方向    | 和太小移左、太大移右   | 移两边都可能变好 → 不能夹逼，需 DP            |
| 求「最接近」而非「等于」 | 维护当前最优 `res` | 求等于 → LC 15，需去重跳过相同三元组          |
| 保证唯一解        | 不用处理多解 / 去重  | 多解 → 需跳过重复元素                    |

**判断流程**：

```
从数组选多个数，和与 target 有关？
  ├── 无序、顺序无关？
  │     ├── 是 → 先排序
  │     └── 否 → 考虑位置约束，排序可能不适用
  └── 选几个数？
        ├── 2 个 → 哈希 O(n) 或 排序双指针 O(n)
        ├── 3 个 → ✅ 固定 i + 双指针 O(n²)
        └── 4 个 → 固定 i,j + 双指针 O(n³)
```

#### 方法约束

- **约束**：对撞双指针需要排序后「移左单调增、移右单调减」；固定外层枚举不会漏解
- **本题**：满足。三数之和 = `nums[i] + nums[left] + nums[right]`，i 固定时只剩两数夹逼
- **易混淆**：
  - 和 LC 15 三数之和几乎同一套代码，但 15 要 `sum==0` 且去重；16 要维护最接近值，`sum==target` 可直接返回
  - 不是「最小绝对差」类题（LC 1200 排序后只看相邻），这里是三数组合，必须枚举第三个数

### 第二步：读题与盲猜

**题目核心**：选三个不同下标的数，使三数之和与 `target` 的绝对差最小，返回该和。

**第一直觉**：三重循环枚举 (i, j, k)，O(n³)，n=1000 约 10⁹ 次运算，边界上可能 TLE。

**盲猜优化方向**：

- **数据结构**：排序后的数组 + 左右双指针
- **时间复杂度**：O(n²)（外层固定 i，内层双指针 O(n)）
- **关键洞察**：固定 `nums[i]` 后，问题退化为「有序数组上找两数之和最接近 `target - nums[i]`」——和 15 题同构，只是目标从 0 变成 `target - nums[i]`，评价从「等于」变成「绝对差最小」

### 第三步：最优解法

#### 核心转换

```
三数之和最接近 target
  ⇔ 固定 nums[i]，在剩余有序段找两数之和最接近 (target - nums[i])
```

#### 状态定义

- `res`：目前为止三数之和与 `target` 最接近的值
- 外层 `i`：第一个数的下标（排序后枚举）
- `left = i+1`，`right = n-1`：夹逼剩余两数

#### 核心状态转移（破局眼）

```python
s = nums[i] + nums[left] + nums[right]
if abs(s - target) < abs(res - target): res = s   # 更新最接近
if s > target:  right -= 1   # 和太大，缩小
elif s < target: left += 1   # 和太小，放大
else: return s               # 精确命中，不可能更近了
```

#### 关键实现细节

- **先排序**：双指针夹逼的前提；O(n log n) 可并入 O(n²) 总复杂度
- **`res` 初始化**：`nums[0]+nums[1]+nums[2]`，保证有合法初值
- **`sum == target` 早停**：精确等于时差值为 0，直接 `return`
- **无需去重**：题目保证唯一解；即使有多组相同和也只留一个答案
- **与 LC 15 的差异**：15 在 `sum==0` 时双指针同时跳过重复；16 不需要

### 核心代码（Python）

```python
def threeSumClosest(nums: list[int], target: int) -> int:
    nums.sort()
    res = nums[0] + nums[1] + nums[2]
    n = len(nums)

    for i in range(n - 2):
        left, right = i + 1, n - 1
        while left < right:
            s = nums[i] + nums[left] + nums[right]
            if abs(s - target) < abs(res - target):
                res = s
            if s > target:
                right -= 1
            elif s < target:
                left += 1
            else:
                return s
    return res
```

### 第四步：拆解记忆点

#### 一句话破局眼

> **LeetCode 16 最接近的三数之和：排序 + 固定 i + 双指针夹逼；每步更新最接近值，精确命中直接返回。**

#### 复杂度对比

| 方法 | 时间 | 空间 | 适用性 |
|------|------|------|--------|
| 三重枚举 | O(n³) | O(1) | n≤100 可过，本题边界勉强 |
| 排序 + 双指针 | O(n²) | O(1) 或 O(log n) 排序栈 | ✅ 最优 |

#### 关键理解点

1. **为什么排序后能双指针？** 固定 i 后，剩余数组有序，移 left 只增、移 right 只减，有明确方向，不会漏掉最优 pair。
2. **为什么 `sum==target` 能直接 return？** 绝对差最小值是 0，已不可能更优。
3. **为什么比 LC 15 简单？** 不用收集所有三元组、不用跳过重复值，只维护一个 `res`。
4. **`res` 为什么要初始化前三项之和？** 保证至少有一组合法三数作为比较基准，避免 `res` 无初值。
