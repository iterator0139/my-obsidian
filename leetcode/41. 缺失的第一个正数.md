给你一个未排序的整数数组 `nums` ，请你找出其中没有出现的最小的正整数。

请你实现时间复杂度为 `O(n)` 并且只使用常数级别额外空间的解决方案。

**示例 1：**

**输入：**nums = [1,2,0]
**输出：**3
**解释：**范围 [1,2] 中的数字都在数组中。

**示例 2：**

**输入：**nums = [3,4,-1,1]
**输出：**2
**解释：**1 在数组中，但 2 没有。

**示例 3：**

**输入：**nums = [7,8,9,11,12]
**输出：**1
**解释：**最小的正数 1 没有出现。

**提示：**

- `1 <= nums.length <= 105`
- `-231 <= nums[i] <= 231 - 1`

### 第一层：如果没有空间限制，正常人会怎么做？

如果你在日常写业务代码，让你找缺失的第一个正数，而且要求 $O(N)$ 时间。你会毫不犹豫地写出以下逻辑：

1. 弄一个哈希集合（`HashSet`）。
    
2. 遍历数组，把所有的正数都扔进 `HashSet`。
    
3. 从 `1` 开始往上数：1 在不在集合里？2 在不在？3 在不在？
    
4. 第一个不在的数，就是答案。
    

**本质剖析**：这个解法的核心本质是“建立存在性映射”。我们需要一个 $O(1)$ 时间能查询的布尔型记录本：`is_exist[val] = true`。

### 第二层：面对绝境，逼出“内存复用”

现在，面试官（或者极端苛刻的线上生产环境）把你的内存掐断了：**不允许使用额外的 `HashSet`，空间必须是 $O(1)$。**

这时候，工程思维开始发力：

既然我不能申请新的内存，而我又迫切需要一个大小为 $N$ 的布尔数组来做映射，我该去哪里找这块内存？

环顾四周，**传入的这个原数组 `nums`，不就是一块现成的大小为 $N$ 的内存吗？！**

**核心转化来了**：

在算法的初始阶段，`nums` 是一个“存储业务数据”的容器。

在算法的最终阶段，我们要在物理层面把它**强行变性为“哈希表”**。它的下标代表 `Value`，它的值代表 `is_exist`。

怎么复用这块内存？在工程上，通常有两种流派：

#### 流派 A：原地标记流（Sign-bit 状态复用）

这是底层 C++ 和内核开发最喜欢的套路。一个 32 位的 int，它不仅能存数字，它的**符号位（正负号）还可以当成一个独立的 boolean 变量来用！**

1. **清洗数据**：先把数组里那些没用的负数和大于 $N$ 的数，全部统一变成 $N+1$。这时候，数组里所有的数字都是纯粹的正数了。
    
2. **打标记（重点）**：遍历数组。比如我读到了数字 `3`，我就知道“数字 3 是存在的”。我就跑到下标 `2`（即 3-1）的位置，**把那里的数字变成负数**（加个负号）。
    
    - _注意：我不覆盖它原来的绝对值，我只改符号！原来那个位置的数字不管是什么，它加了负号以后，绝对值依然保留着，不影响后面的读取。_
        
3. **查字典**：再遍历一遍数组。如果下标 `i` 对应的值是**正数**，说明根本没有人来给它打过负号标记，说明数字 `i+1` 从来没出现过！直接返回 `i+1`。
    

在这个流派里，原数组的内存被劈成了两半用：**绝对值部分依然在老老实实扮演“原数组”，符号位部分被我们强行征用成了“HashSet”！**

#### 流派 B：空间置换流（也就是刚才的“萝卜坑/原地哈希”）

相比于打标记，这个流派更激进。它连符号位都不屑于用，它直接“鸠占鹊巢”。

既然我要把 `nums` 变成一个哈希表，而哈希表的完美状态是 `nums[0] = 1, nums[1] = 2`。

那我看到数字 `3` 的时候，我直接把它**塞到它作为哈希表该去的位置（下标 2）**，顺手把原来待在下标 2 的那个倒霉蛋给抽出来，看看这个倒霉蛋又是谁，再把它送到它该去的地方。

这就形成了一个**链式置换**，直到把所有的值都安顿到哈希表的位置上。

### 🌟 终极顿悟：它到底是什么“转化”思想？

现在回过头来看，你还会觉得它是一个生硬的 Trick 吗？

这道题其实完成了一个非常高级的转化：

**数据结构的“生命周期转化”。**

在很多高级的广告检索系统或者引擎底层，当内存吃紧时，一块内存在不同的阶段承担的职责是完全不同的。

这道题就是逼着你在运行时，**把一个单纯的 Array，原地“熔铸”成一个 Direct-Address Hash Table（直接寻址哈希表）**。

- “萝卜坑”交换法：是在物理上把元素挪过去，完成哈希表的构建。
    
- “符号位标记”法：是把原内存按 bit 拆分，叠加了一层虚拟的布尔映射。
    

这才是这道题真正牛逼的地方：它考察的不是你会不会背代码，而是考察当你在高并发、大吞吐、内存被锁死在常数级别时，你敢不敢对输入数据本身“下黑手”，通过**状态复用**榨干它的最后一滴价值。


暴力写法，直接一个map实现O(1)查找，然后从1到n去遍历查询。因为对一个长度为n的数组来说，最大的正数就是n了

```

def firstMissingPositiveNumber(nums: List[int]):
	data = {}
	n = len(nums)
	for num in nums:
		data[num] = 1
	
	for i in range(1, n):
		if i not in data.keys():
			return i

```

现在只能用常数级别的内存，那意味着我们不能新开内存来维护这个存在映射关系。
常用的方法是在原始数组里做符号标记和鸽笼交换。
- 符号标记往往要求内部数据都是正数或者负数，不考虑符号对原始数据的影响
- 鸽笼交换的局限性
	- 值域必须是可控的，比如出现100000，这个时候我们应该要忽略，超出范围的数必须可以“安全忽略”
	- 允许破坏原数组
	- 防止重复值引发死循环

```
def firstMissingPositiveNumber(nums: List[int]):
	
	n = len(nums)
	for i in range(n):
		while 1<=nums[i]<= n and nums[nums[i] - 1] != nums[i]:
			correct_idx = nums[i] - 1  
			nums[i], nums[correct_idx] = nums[correct_idx], nums[i]
	
	for i, num in enumerate(nums):
		if num != i + 1:
			return i + 1
	return n+1
```
