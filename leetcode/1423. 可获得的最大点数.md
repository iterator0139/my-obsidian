几张卡牌 **排成一行**，每张卡牌都有一个对应的点数。点数由整数数组 `cardPoints` 给出。

每次行动，你可以从行的开头或者末尾拿一张卡牌，最终你必须正好拿 `k` 张卡牌。

你的点数就是你拿到手中的所有卡牌的点数之和。

给你一个整数数组 `cardPoints` 和整数 `k`，请你返回可以获得的最大点数。

**示例 1：**

**输入：**cardPoints = [1,2,3,4,5,6,1], k = 3
**输出：**12
**解释：**第一次行动，不管拿哪张牌，你的点数总是 1 。但是，先拿最右边的卡牌将会最大化你的可获得点数。最优策略是拿右边的三张牌，最终点数为 1 + 6 + 5 = 12 。

**示例 2：**

**输入：**cardPoints = [2,2,2], k = 2
**输出：**4
**解释：**无论你拿起哪两张卡牌，可获得的点数总是 4 。

**示例 3：**

**输入：**cardPoints = [9,7,7,9,7,7,9], k = 7
**输出：**55
**解释：**你必须拿起所有卡牌，可以获得的点数为所有卡牌的点数之和。

**示例 4：**

**输入：**cardPoints = [1,1000,1], k = 1
**输出：**1
**解释：**你无法拿到中间那张卡牌，所以可以获得的最大点数为 1 。 

**示例 5：**

**输入：**cardPoints = [1,79,80,1,1,1,200,1], k = 3
**输出：**202

**提示：**

- `1 <= cardPoints.length <= 10^5`
- `1 <= cardPoints[i] <= 10^4`
- `1 <= k <= cardPoints.length`

## 破局眼 🎯

> **取走的 k 张牌必然来自左端 i 张 + 右端 k-i 张（中间 n-k 张是连续的）。枚举 i 即可，不用真的递归搜索。**

你的递归直觉是对的——`f(l, r, k)` 有重叠子结构，但 n ≤ 10⁵ 不允许 O(n²) DP。

**关键转折**：只能从首尾取 → 取走的牌永远分裂在两端 → 中间剩的牌是连续子数组。

### 正向思维：枚举左右各取几张

用前缀和，枚举左边取 i 张（0 ≤ i ≤ k），自动右边取 k-i 张。

```python
def maxScore(self, cardPoints: List[int], k: int) -> int:
    n = len(cardPoints)
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + cardPoints[i]

    ans = 0
    for i in range(k + 1):                    # 左边取 i 张
        left_sum = prefix[i]                   # cardPoints[0..i-1]
        right_sum = prefix[n] - prefix[n - k + i]  # cardPoints[n-k+i..n-1]
        ans = max(ans, left_sum + right_sum)
    return ans
```

O(k) 时间，由于 k ≤ n，最坏 O(n)。

### 逆向思维：滑动窗口求最小连续子数组和

拿走的 = 总和 - 剩下的。剩下的必须是连续 `n-k` 张（中间那段）。

```python
def maxScore(self, cardPoints: List[int], k: int) -> int:
    n = len(cardPoints)
    total = sum(cardPoints)
    if k == n:
        return total

    window_size = n - k
    min_sum = cur = sum(cardPoints[:window_size])

    for i in range(window_size, n):
        cur += cardPoints[i] - cardPoints[i - window_size]
        min_sum = min(min_sum, cur)

    return total - min_sum
```

O(n) 时间，O(1) 空间。

## 什么性质的题可以用这个解法？

本题本质是 **"两端取数 + 中间连续"** 模式。

### 必要条件

| 性质 | 本题体现 | 反例（不能用） |
|------|---------|-------------|
| **只能从两端取** | 每次拿开头或结尾 | 可以从任意位置取 → 贪心/DP 不同 |
| **恰好取 k 个** | k 固定 | 无数量限制 → 直接贪心 |
| **两端取构成完整解** | 左取 i 个，右取 k-i 个 | 中间也能跳过（可选）→ 不同模型 |
| **元素独立求和** | 点数直接相加 | 取牌有联动效果 → 复杂 DP |

### 判断流程

```
从数组两端取元素（每次只能取首或尾）？
  ├── 取的元素恰好构成一个"前缀 + 后缀"？
  │     ├── 是 → ✅ 枚举左右分配 + 前缀和
  │     └── 否 → 中间可以跳过？
  │           ├── 是 → DP 区间（如 LC 877 石子游戏）
  │           └── 否 → 其他
  └── 能否转化为"剩下的中间是连续的"？
        ├── 是 → ✅ 逆向思维：总和 - 最小窗口和
        └── 否 → 直接枚举左右分配
```

### 同类题

| 题目 | 模式 | 解法 |
|------|------|------|
| LC 1423 最大点数 | 两端取 k 个 | 枚举左右分配 / 滑动窗口 |
| LC 1652 拆炸弹 | 首尾相连取 k 个 | 前缀和 + 滑动窗口 |
| LC 209 长度最小的子数组 | 中间连续和 ≥ target | 滑动窗口 |

> **核心思维转换：只从两端取 → 剩下的是连续的 → 用滑动窗口求剩下的最小值。**
