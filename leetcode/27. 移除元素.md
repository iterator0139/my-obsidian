给你一个数组 `nums` 和一个值 `val`，你需要 **[原地](https://baike.baidu.com/item/%E5%8E%9F%E5%9C%B0%E7%AE%97%E6%B3%95)** 移除所有数值等于 `val` 的元素。元素的顺序可能发生改变。然后返回 `nums` 中与 `val` 不同的元素的数量。

假设 `nums` 中不等于 `val` 的元素数量为 `k`，要通过此题，您需要执行以下操作：

- 更改 `nums` 数组，使 `nums` 的前 `k` 个元素包含不等于 `val` 的元素。`nums` 的其余元素和 `nums` 的大小并不重要。
- 返回 `k`。

**用户评测：**

评测机将使用以下代码测试您的解决方案：

int[] nums = [...]; // 输入数组
int val = ...; // 要移除的值
int[] expectedNums = [...]; // 长度正确的预期答案。
                            // 它以不等于 val 的值排序。

int k = removeElement(nums, val); // 调用你的实现

assert k == expectedNums.length;
sort(nums, 0, k); // 排序 nums 的前 k 个元素
for (int i = 0; i < k; i++) {
    assert nums[i] == expectedNums[i];
}

如果所有的断言都通过，你的解决方案将会 **通过**。

**示例 1：**

**输入：**nums = [3,2,2,3], val = 3
**输出：**2, nums = [2,2,_,_]
**解释：**你的函数应该返回 k = 2, 并且 nums 中的前两个元素均为 2。
你在返回的 k 个元素之外留下了什么并不重要（因此它们并不计入评测）。

**示例 2：**

**输入：**nums = [0,1,2,2,3,0,4,2], val = 2
**输出：**5, nums = [0,1,4,0,3,_,_,_]
**解释：**你的函数应该返回 k = 5，并且 nums 中的前五个元素为 0,0,1,3,4。
注意这五个元素可以任意顺序返回。
你在返回的 k 个元素之外留下了什么并不重要（因此它们并不计入评测）。

**提示：**

- `0 <= nums.length <= 100`
- `0 <= nums[i] <= 50`
- `0 <= val <= 100`

## 五分钟读题法分析

### 第一步：分析性质

#### 识别信号

> **数组原地删掉等于 val 的元素 → 快指针扫描、慢指针维护「保留区」写入位置；和 LC 26 同一套读写手势。**

#### 题目性质

- **数据规模**：n ≤ 100，O(n) 一趟足够
- **数据结构**：无序数组（顺序可打乱）
- **目标类型**：原地修改 + 返回保留元素个数 k
- **范围约束**：前 k 位是不等于 val 的元素，顺序 **可以变**
- **操作特征**：按条件过滤，不是按「相邻去重」

#### 性质 → 方法

| 性质          | 本题体现                | 若不满足则…                     |
| ----------- | ------------------- | -------------------------- |
| 原地删除/过滤     | 不能开新数组              | 可开新数组 → 直接 append          |
| 保序不要求       | 读写指针从左扫即可           | 要保序 → 同样用慢指针写，只是不能从两端 swap |
| 删除条件固定      | `nums[i] == val` 丢掉 | 多条件 → 改 if 判断              |
| 与 LC 26 同手势 | 快扫慢写                | 26 是有序去重，判断条件不同            |

**判断流程**：

```
数组原地删掉部分元素？
  ├── 要保留相对顺序 → ✅ 快扫慢写（slow = 下一写入位）
  ├── 顺序无所谓 + val 很少 → 可选左右夹逼 swap（少写元素）
  └── 不要求 O(1) 空间 → 新数组过滤
```

#### 方法约束

- **约束**：读写双指针有效，需要「慢指针左侧始终是合法保留前缀」
- **本题**：满足。`nums[fast] != val` 时写入 `nums[slow]`，保留区始终正确
- **易混淆**：
  - LC 26：有序、与 `nums[slow]` 比是否重复
  - LC 283 移动零：把 0 挪到末尾，手势类似但语义是「把非零往前挤」

### 第二步：读题与盲猜

**题目核心**：删掉所有等于 `val` 的元素，原地完成，返回剩余个数 k。

**第一直觉**：新建数组，遍历 `append` 不等于 val 的。O(n) 但 O(n) 空间。

**盲猜优化方向**：

- **数据结构**：同向双指针（快读慢写）
- **时间复杂度**：O(n)
- **关键洞察**：`slow` 指向下一个「保留元素」的写入位置；`fast` 扫到非 val 就写入并 `slow++`

---

### 第三步：最优解法

#### 核心转换

```
原地移除 val
  ⇔ 把不等于 val 的元素依次挤到 nums[0..k-1]
  ⇔ slow 维护「下一个写入位置」
```

#### 状态定义

- `slow`：下一个保留元素的写入下标（也是当前保留区长度）
- `fast`：扫描指针，遍历整个数组

#### 核心状态转移（破局眼）

```python
if nums[fast] != val:
    nums[slow] = nums[fast]
    slow += 1
# fast 每轮 +1
return slow
```

#### 关键实现细节

- **`slow` 含义与 LC 26 略不同**：26 的 `slow` 是「已去重区间末尾」；27 的 `slow` 是「下一写入位」，逻辑等价于「保留区长度」
- **相等时也要写吗？** `nums[fast] == val` 直接跳过，不写
- **`nums[fast] != val` 时是否总要赋值？** 当 `slow == fast` 时可以省略赋值（已在正确位置），但统一写 `nums[slow] = nums[fast]` 更简洁
- **返回值**：`slow`（即 k），不是 `slow - 1`

#### 变体：左右夹逼（val 很少时少写）

```python
left, right = 0, len(nums) - 1
while left <= right:
    if nums[left] == val:
        nums[left] = nums[right]
        right -= 1
    else:
        left += 1
return left
```

适合要删除的元素很少、想减少赋值次数的场景；面试主解法仍推荐快慢读写。

### 核心代码（Python）

```python
def removeElement(nums: list[int], val: int) -> int:
    slow = 0
    for fast in range(len(nums)):
        if nums[fast] != val:
            nums[slow] = nums[fast]
            slow += 1
    return slow
```

### 第四步：拆解记忆点

#### 一句话破局眼

> **LeetCode 27 移除元素：快扫慢写，不等于 val 就写到 slow 并 slow++，返回 slow。**

#### 复杂度对比

| 方法 | 时间 | 空间 | 适用性 |
|------|------|------|--------|
| 新数组过滤 | O(n) | O(n) | 不要求原地 |
| 快扫慢写 | O(n) | O(1) | ✅ 主解法 |
| 左右 swap | O(n) | O(1) | val 极少时少写 |

#### 关键理解点

1. **和 LC 26 只差 if 条件**：26 看 `nums[fast] != nums[slow]`；27 看 `nums[fast] != val`。
2. **`slow` 就是 k**：写入完成后，保留区为 `nums[0:slow]`。
3. **顺序可以变**：所以左右 swap 写法也合法；26 必须保序，不能用 swap 打乱相对顺序（有序去重场景）。
4. **和 LC 283 移动零**：283 是「把非零往前写」，判断 `nums[fast] != 0`，几乎同一套代码。
