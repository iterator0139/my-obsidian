### 5分钟刷题法步骤：

1. **读题与盲猜（1分钟）：** 盯着题目，在草稿纸上写下第一直觉的数据结构（如：单调栈、双指针）和预估时间复杂度。
    
2. **看最优解法（2分钟）：** 直接打开力扣题解区，寻找点赞最高、写得最优雅的**核心状态转移方程**或**指针移动逻辑**。
    
3. **拆解记忆点（2分钟）：** 在笔记本上只记录一行字，点出这道题的“破局眼”（例如：“_LeetCode 42 接雨水：单调栈找左右边界，或者双指针按列收缩_”）。
    
4. **滚动复习：** 每天临睡前，把这天看过的 30-40 道题的”破局眼”像过电影一样在脑海里快速过一遍。

## 解题框架速查（读题 1 分钟内快速判断）

### 1. 滑动窗口 → 单调队列 / 双指针

```
问题是否求连续子数组/子串？
  ├── 否 → 不用滑动窗口
  └── 是 → 约束条件是否关于窗口的”统计量”（max/min/sum/unique count）？
        ├── 否 → 不用
        └── 是 → 窗口移动时统计量能 O(1) 维护？
              ├── 否 → 考虑有序容器 O(n log n)
              └── 是 → ✅ 滑动窗口 + 单调队列 / 双指针
```

**窗口单调性条件**（必满足）：窗口越大条件越难满足（或越容易），扩窗变差缩窗变好。

| 约束类型 | 数据结构 | 代表题 |
|---------|---------|-------|
| `max - min ≤ limit` | 两个 deque | LC 1438 |
| 窗口 max | 一个 deque（单调递减） | LC 239 |
| 和/积 ≤ target | 双指针 | LC 209 |
| 窗口内字符覆盖 | 哈希表 + 双指针 | LC 76 |

### 2. 子数组/子序列 → 动态规划

```
求最值/方案数/可行性？
  ├── 子数组（连续）→ 一维 DP /  Kadane
  ├── 子序列（不连续）→ 二维 DP
  └── 两个序列/字符串 → 二维 DP（LCS / 编辑距离）
```

### 3. 下一个更大/更小元素 → 单调栈

```
求每个元素右侧/左侧第一个比它大/小的元素？
  ├── 求更大 → 单调递减栈（遇到更大的结算）
  └── 求更小 → 单调递增栈（遇到更小的结算）
```

### 4. Top K / 第 K 大 → 堆 / 快速选择

```
求前 K 大/小 或 第 K 大/小？
  ├── 数据量大 → 堆 O(n log k)
  └── 数据量小 → 排序 O(n log n)
```

### 5. 两数/三数/四数之和 → 双指针 / 哈希表

```
求特定和的组合？
  ├── 无序数组 → 哈希表
  ├── 有序数组 → 双指针
  └── 多个数 → 固定一个 + 双指针
```

### 6. 数组有序 / 排序相关

```
数组是否有序？
  ├── 已排序 → 二分查找 / 双指针
  ├── 部分有序（旋转） → 变种二分
  └── 未排序 → 看数据范围决定暴力/哈希/排序
```

### 7. 小数据量 → 暴力

```
数据范围：
  ├── n ≤ 20    → 回溯 / 状态压缩
  ├── n ≤ 100   → O(n³) 暴力
  ├── n ≤ 1000  → O(n²) 双循环
  ├── n ≤ 10^5  → O(n log n) 排序/二分
  └── n ≤ 10^6  → O(n) 贪心/哈希/滑动窗口
```

> **破局第一步不是想算法，而是根据题目特征快速定位到上述某一大类。大类定对了，细节解法呼之欲出。**
