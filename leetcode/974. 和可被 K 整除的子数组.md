给你一个整数数组 `nums` 和一个整数 `k`，返回其中元素之和可被 `k` 整除的非空 **子数组** 的数目。

**子数组** 是数组中 **连续** 的部分。

**示例 1：**

**输入：** nums = [4,5,0,-2,-3,1], k = 5
**输出：** 7
**解释：**
有 7 个子数组满足其元素之和可被 k = 5 整除：
[4, 5, 0, -2, -3, 1], [5], [5, 0], [5, 0, -2, -3], [0], [0, -2, -3], [-2, -3]

**示例 2：**

**输入：** nums = [5], k = 9
**输出：** 0

**提示：**

- `1 <= nums.length <= 3 * 10^4`
- `-10^4 <= nums[i] <= 10^4`
- `2 <= k <= 10^4`

## 五分钟读题法分析

### 第一步：分析性质

#### 识别信号

> **连续子数组 + 和的条件（可被 K 整除）→ 前缀和；出现取模/整除 → 同余配对，哈希表记余数出现次数。**

#### 题目性质

- **数据规模**：n ≤ 3×10⁴，暴力 O(n²) 会 TLE
- **数据结构**：整数数组，元素可为负
- **目标类型**：计数（有多少个满足条件的连续子数组）
- **范围约束**：必须是**连续**子数组
- **操作特征**：子数组和 % k == 0，不是求最值也不是构造

#### 性质 → 方法

| 性质           | 本题体现                               | 若不满足则…                     |
| ------------ | ---------------------------------- | -------------------------- |
| 连续子数组 + 和的条件 | 和可被 k 整除                           | 非连续 → 子序列 / DP             |
| 前缀和差表示子数组和   | sum(i+1,j) = prefix[j] - prefix[i] | 无「和」条件 → 滑动窗口 / 双指针        |
| 整除等价于同余      | (a-b) % k == 0 ⟺ a%k == b%k        | 要求和恰好等于 K → 560 查 prefix-K |
| 计数所有合法对      | 相同余数每对都算                           | 求最长 → 525 只存首次索引           |

**判断流程**：

```
是否「连续子数组 + 和的条件」？
  ├── 是 → 前缀和
  │     ├── 和恰好 = K？ → 560：哈希表查 prefix - K
  │     ├── 和 % K = 0？ → 974：哈希表查相同余数
  │     └── 0/1 数量相等？ → 525：0→-1，查相同前缀和 + 首次索引
  └── 否 → 其他方法
```

#### 方法约束

- **约束**：前缀和 + 哈希表成立需要「子数组和 = 两端前缀和之差」；取模需保证余数在 `[0, k-1]`（负数要修正）
- **本题**：满足；元素可为负，但同余性质仍成立
- **易混淆**：不要套滑动窗口——窗口内和 % k 没有单调性；不要套 525 的「只存首次」——本题要**计数**所有配对

### 第二步：读题与盲猜

**题目核心**：统计有多少个连续子数组，其元素之和能被 k 整除。

**第一直觉**：枚举所有子数组 [i, j]，求和判断 % k == 0，O(n²)，n=3×10⁴ 会超时。

**盲猜优化方向**：

- **数据结构**：前缀和 + 哈希表（余数 → 出现次数）
- **时间复杂度**：O(n)
- **关键洞察**：`(prefix[j] - prefix[i]) % k == 0` 等价于 `prefix[j] % k == prefix[i] % k`——找相同余数配对计数

---

### 第三步：最优解法

#### 核心转换

子数组 `nums[i+1..j]` 的和：

```
sum(i+1, j) = prefix[j] - prefix[i]
```

要被 k 整除：

```
(prefix[j] - prefix[i]) % k == 0  ⟺  prefix[j] % k == prefix[i] % k
```

从「差等于某个值」变成「余数相同」——这是 974 和 560 的分水岭。

#### 状态定义

- `prefix`：从数组开头到当前位置的前缀和
- `count[r]`：遍历过程中，前缀和余数为 `r` 已出现的次数
- `ans`：满足条件的子数组总数

#### 核心状态转移（破局眼）

```
每步更新 prefix = (prefix + nums[i]) % k
ans += count[prefix]          # 之前每个相同余数，都和当前位置配成一段合法子数组
count[prefix] += 1
```

#### 关键实现细节

- **初始化 `count[0] = 1`**：空前缀余数为 0；处理「从数组开头就整除」的子数组（如 `[5]` 且 k=5）
- **负数取模**：Python 的 `%` 自动归到 `[0, k-1)`；Java/C++ 需 `(x % k + k) % k`
- **先累加 ans 再更新 count**：避免把当前位置和自己配对
- **和 560 的区别**：560 查 `prefix - K`；974 查**同一个余数**

### 核心代码（Python）

```python
def subarraysDivByK(nums: list[int], k: int) -> int:
    count = {0: 1}
    prefix = 0
    ans = 0
    for x in nums:
        prefix = (prefix + x) % k
        ans += count.get(prefix, 0)
        count[prefix] = count.get(prefix, 0) + 1
    return ans
```

### 第四步：拆解记忆点

#### 一句话破局眼

> **LeetCode 974 和可被 K 整除的子数组：前缀和取模，相同余数配对计数。**

#### 复杂度对比

| 方法 | 时间复杂度 | 空间复杂度 | 适用性 |
|------|-----------|-----------|--------|
| 暴力枚举子数组 | O(n²) | O(1) | n 小可用 |
| **前缀和 + 余数哈希** | **O(n)** | **O(k)** | **本题最优** |

#### 关键理解点

1. **为什么是相同余数？** `(a-b) % k == 0` 当且仅当 `a % k == b % k`——整除就是同余
2. **为什么 count[0]=1？** 空前缀余数 0 算一次，否则「从 index 0 开头就整除」的子数组会漏计
3. **为什么先 ans 再 count++？** 不能把当前位置和自身配对；和 560 一样，只用**之前**出现过的前缀和
4. **和 560 / 525 怎么分？** 560 差等于 K；974 余数相同计数；525 余数相同但只存首次索引求最长
