给你一个字符串 `s`。我们要把这个字符串划分为尽可能多的片段，同一字母最多出现在一个片段中。

注意，划分结果需要满足：将所有划分结果按顺序连接，仍然能够得到原字符串 `s`。

返回一个表示字符串每个片段长度的列表。

**示例 1：**

**输入：** s = "ababcbacadefegdehijhklij"
**输出：** [9,7,8]
**解释：**
划分结果为 "ababcbaca"、"defegde"、"hijhklij"。
每个字母最多出现在一个片段中。
像 "ababcbacadefegde", "hijhklij" 的划分是错误的，因为划分的片段数较少。

**示例 2：**

**输入：** s = "eccbbbbdec"
**输出：** [10]

**提示：**

- `1 <= s.length <= 500`
- `s` 仅由小写英文字母组成

## 五分钟读题法分析

### 第一步：分析性质

#### 识别信号

> **同一字母不能跨段 → 每个字母的 `[first, last]` 跨度必须在同一段；合并重叠跨度即得最优划分，贪心扫描是在线做同一件事。**

#### 题目性质

- **数据规模**：n ≤ 500，暴力也能过，但贪心 O(n) 更自然
- **数据结构**：字符串，26 个小写字母
- **目标类型**：构造划分 + 段数尽量多（贪心）
- **约束特征**：字母 **不能跨段** → 每个字母从第一次到最后一次出现必须在同一段
- **局部 vs 全局**：当前段能否在此切断，取决于段内所有字母是否都已「包到」各自的最远末次位置

#### 性质 → 方法

| 性质 | 本题体现 | 若不满足则… |
|------|---------|------------|
| 元素不能跨段 | 同字母只能在一个片段 | 无此约束 → 随意切 |
| 每字母有固定跨度 | 第一次出现到最后一次出现 `[first, last]` | 跨度重叠的字母必须在同一段 |
| 合并重叠跨度 = 合法且最优 | 合并后每个大区间的个数 = 最多段数 | 无跨段约束 → 随意切 |
| 贪心扫描等价于在线合并 | 扫描时 `end = max(end, last[c])` | 需全局最优组合 → DP |
| 切断条件单调 | `i == end` 时必可切 | — |

**判断流程**：

```
同一元素不能跨段？
  ├── 是 → 预处理每个字母的 [first, last] 跨度
  │     ├── 写法 A：合并所有重叠跨度 → 每个合并后的大区间 = 一段（合法且段数最多）
  │     └── 写法 B：只存 last，扫描时 end = max(end, last[c])，i == end 切段（等价于在线合并）
  └── 否 → 其他模型
```

#### 方法约束

- **约束**：字母跨度有重叠就必须在同一段；合并重叠跨度后得到的大区间互不相交，且已是「能切的最细粒度」，段数自然最多
- **本题**：满足
- **易混淆**：不是滑动窗口；**合并区间就是正确答案**，贪心只是等价的一遍扫实现，不必二选一

### 第二步：读题与盲猜

**题目核心**：把字符串切成尽量多的段，使每个字母只出现在一个段里。

**第一直觉**：预处理每个字母的 `[first, last]` 区间，合并重叠区间——**既合法，又段数最多**。

**盲猜优化方向**：

- **数据结构**：`first/last` 数组，或只存 `last` 做一遍扫描
- **时间复杂度**：O(n) 预处理 + O(n) 合并/扫描
- **关键洞察**：合并后的大区间个数 = 最多段数；贪心 `i == end` 切段是在线做同一件事

### 第三步：最优解法

#### 核心转换

字母 `c` 的合法跨度是 `[first[c], last[c]]`：只要段里出现了 `c`，这段就必须至少延伸到 `last[c]`。

- **合并区间思路**：所有跨度有重叠的字母必须在同一段 → 合并重叠区间 → 每个合并后的大区间 = 一段划分
- **贪心思路**：从左扫描，遇到字母就把当前段右边界 `end` 往右推到 `last[c]` → `i == end` 时当前大区间结束，立刻切段

两种写法**结果完全相同**；贪心是在线合并，代码更短。

#### 合并区间版（写法 A）

```
1. 预处理每个出现过的字母的 [first, last]
2. 按 first 排序，合并重叠区间（end 取 max）
3. 每个合并后区间的长度 = 答案的一段
```

合并后的大区间已是「能切的最细粒度」——在大区间内部任意切一刀都会让某字母跨段，所以段数最多。

#### 贪心扫描版（写法 B）

当前段从 `start` 开始，扫描到 `i` 时：

```
end = max(end, last[s[i]])   # 段内每遇到一个字母，就把右边界往右推
```

当 `i == end`，说明 `[start, i]` 恰好对应一个合并后的大区间，**此处必可切，且应立刻切**。

#### 状态定义

- `last[c]`：字符 `c` 在字符串中**最后一次**出现的下标
- `start`：当前段左边界
- `end`：当前段必须延伸到的最远右边界
- `ans`：各段长度列表

#### 核心状态转移（破局眼）

```
预处理：last[c] = c 的最远末次下标

start = 0, end = 0
for i in range(n):
    end = max(end, last[s[i]])
    if i == end:
        ans.append(i - start + 1)
        start = i + 1
```

#### 关键实现细节

- **合并区间**：需要 `first` 和 `last`；合并后区间个数 = 段数，不是「粗分变少」，而是「重叠的必须并成一段」
- **贪心扫描**：只需 `last`；扫描从左到右，`end` 自然扩到当前合并大区间的右边界
- **`i == end` 的含义**：当前段内每个字母都不会在 `i` 之后再出现，等价于走完一个合并后的大区间

### 核心代码（Python）

**写法 A：合并区间**

```python
def partitionLabels_merge(s: str) -> list[int]:
    first, last = {}, {}
    for i, c in enumerate(s):
        if c not in first:
            first[c] = i
        last[c] = i

    intervals = sorted([first[c], last[c]] for c in first)
    merged = []
    for start, end in intervals:
        if not merged or start > merged[-1][1]:
            merged.append([start, end])
        else:
            merged[-1][1] = max(merged[-1][1], end)

    return [end - start + 1 for start, end in merged]
```

**写法 B：贪心扫描（等价，更短）**

```python
def partitionLabels(s: str) -> list[int]:
    last = {c: i for i, c in enumerate(s)}
    start = end = 0
    ans = []
    for i, c in enumerate(s):
        end = max(end, last[c])
        if i == end:
            ans.append(i - start + 1)
            start = i + 1
    return ans
```

### 第四步：拆解记忆点

#### 一句话破局眼

> **LeetCode 763 划分字母区间：字母跨度合并 = 最优划分；贪心版只存 last，扩展 end，`i == end` 切段。**

#### 复杂度对比

| 方法 | 时间复杂度 | 空间复杂度 | 适用性 |
|------|-----------|-----------|--------|
| **合并区间（first + last）** | **O(n)** | **O(1)** | **合法且最优，思路直观** |
| **贪心扫描（只存 last）** | **O(n)** | **O(1)** | **与合并等价，代码更短** |

#### 关键理解点

1. **合并区间是不是答案？** 是。合并重叠跨度后，每个大区间 = 一段合法划分，且段数最多
2. **为什么合并后段数最多？** 大区间内部不能再切——否则某字母会跨段；合并后的大区间个数就是「能切的最细粒度」
3. **贪心和合并什么关系？** 等价。`end = max(end, last[c])` 是在线合并；`i == end` 等于走完一个合并后的大区间
4. **为什么贪心只存 last？** 扫描从左到右，`first` 隐含在当前段 `start`；合并写法需要显式 `first` 来排序合并
