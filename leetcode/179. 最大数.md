给定一组非负整数 `nums`，重新排列每个数的顺序（每个数不可拆分）使之组成一个最大的整数。

**注意：**输出结果可能非常大，所以你需要返回一个字符串而不是整数。

**示例 1：**

**输入`：`**`nums = [10,2]`
**输出：**`"210"`

**示例 2：**

**输入`：`**`nums = [3,30,34,5,9]`
**输出：**`"9534330"`

**提示：**

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 109`

这道题我的思路是，要最大的整数，那就是高位的数字越大越好，所以我们进行分组排序，9开头的分一组，8开头的分一组，然后对每组再进行排序。

排序的思路是没有问题，但是按情况讨论的方法会有很多边界case的讨论。比如
- 3和30，应该组成330
- 3和34，应该组成343

```
from functools import cmp_to_key

class Solution:
    def largestNumber(self, nums: List[int]) -> str:
        # 1. 将所有数字转为字符串
        strs = [str(num) for num in nums]
        
        # 2. 定义自定义比较函数
        def compare(a, b):
            if a + b > b + a:
                return -1 # a 排在前面
            elif a + b < b + a:
                return 1  # b 排在前面
            else:
                return 0
        
        # 3. 根据自定义规则排序
        strs.sort(key=cmp_to_key(compare))
        
        # 4. 拼接结果
        res = "".join(strs)
        
        # 5. 处理特殊边界：如果数组全是 0，比如 [0, 0]，结果应该是 "0" 而不是 "00"
        return "0" if res[0] == "0" else res
```

下面是组合排序能推广到全数组的证明

我有一个问题，两两可以用这个规则排序，但是整个数组为什么这个排序规则可以得到最后的答案呢？

这是一个非常深刻的问题！在工程实践中，很多时候我们直觉上觉得“局部最优”能推导出“全局最优”，但这往往需要严格的数学和逻辑支撑。

我们要证明“两两排序的规则能够得到整个数组的全局最大值”，本质上需要证明两件事：

1. **这个排序规则是成立的（满足传递性）**：即 A 排在 B 前面，B 排在 C 前面，能推导出 A 一定要排在 C 前面。
    
2. **全局最优性（微扰法/交换法论证）**：证明任何不按照这个规则排列的数组，都可以通过调整变得更大。
    

我们一步步拆解这背后的底层逻辑。

### 一、 规则的合法性：为什么它满足“传递性”？

如果一个自定义排序规则连传递性都不满足（比如 A > B，B > C，结果 C > A），底层排序算法（如快排）就会直接陷入混乱，根本得不到确定性的结果。

我们把两个数字字符串 a 和 b 拼接，本质上是一个数学运算。 假设数字 a 的长度是 La​，数字 b 的长度是 Lb​。 那么把 a 放在 b 前面（即字符串 a+b），在数学上等于：

a×10Lb​+b

我们的排序规则定义为，如果 a 优先于 b（记作 a≻b），则有：

a×10Lb​+b>b×10La​+a

**高能预警：这里有一个非常优雅的数学变形。** 我们将上式移项并提取公因式：

a×10Lb​−a>b×10La​−b

a×(10Lb​−1)>b×(10La​−1)

将两边同时除以 (10La​−1)×(10Lb​−1)，不等式方向不变（因为分母都是正数）：

10La​−1a​>10Lb​−1b​

到这里，真相大白了！ 我们发现，**两个数字组合的大小比较，被完全解耦了！** 它等价于计算每个数字的一个独立“特征值”：f(x)=10Lx​−1x​。

- 如果 a≻b，意味着 f(a)>f(b)。
    
- 如果 b≻c，意味着 f(b)>f(c)。
    

根据基本数学常识，既然 f(a)>f(b) 且 f(b)>f(c)，那必然有 f(a)>f(c)，也就是 a≻c。 **结论：我们的两两比较规则，在数学上是绝对严格且满足传递性的，它是一个合法的全序关系。**

### 二、 全局最优性：为什么排序后就是最大值？

现在我们知道可以把数组像普通数字一样从小到大（或从大到小）排出一个唯一确定的序列了。但为什么这个序列拼接起来的超长字符串，就一定是所有排列组合中最大的呢？

这里我们要用到算法证明中常用的**微扰法（相邻交换法）**。

假设我们通过排序规则得到了一个序列 S。为了方便说明，假设 S 中有两个相邻的元素，前面是 x，后面是 y。 因为它是按照我们的规则排好序的，所以必然满足：x≻y，即 x+y>y+x。

**反证法假设：** 假设存在另一个序列 S′，它拼接出来的结果比我们的 S 还要大。 既然 S′ 与 S 不同，那么在 S′ 中，必然存在至少一对**相邻**的元素，它们的位置与我们定义的规则是相反的（即 y 排在了 x 前面，但实际上 x≻y）。

现在，如果我们在 S′ 中把这一对违背规则的相邻元素 y 和 x 交换位置，变成 x 和 y。

- **局部变化**：根据规则，拼接后的局部子串从 y+x 变成了 x+y，局部数值**变大了**。
    
- **全局变化**：因为它们是相邻的元素，交换它们**完全不影响**它们前面那段字符串，也**完全不影响**它们后面那段字符串。
    
- **整体结果**：整个超大数字字符串的值，因为中间这一小段的变大，而**严格变大了**。
    

这就产生了一个致命的逻辑矛盾：

1. 我们假设 S′ 是最大的。
    
2. 但是我们只要在 S′ 里面找出一对逆序的相邻元素，把它们调换过来，就能得到一个**比 S′ 还要大**的新序列。
    
3. 说明 S′ 根本不是最大的！
    

只要序列中还存在不符合我们规则的相邻元素，我们就可以不断通过交换它们来让整个数字变得更大（这其实就是冒泡排序的物理意义）。直到没有任何一对相邻元素可以交换——此时，数组完全符合我们的排序规则，这时的拼接结果也就达到了真正的**全局最大值**。
