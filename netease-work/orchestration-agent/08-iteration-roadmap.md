# Agent 编排平台迭代规划

## 核心原则

先让 Agent **可描述、可验证、可选择、可恢复**，再让模型承担复杂规划。平台的目标不是增加 Agent 数量，而是提升真实任务交付率。

## 里程碑

### M0：定义任务与交付标准

- 聚焦用例生成、自动化测试、冒烟测试。
- 定义 `TaskSpec`：目标、输入、约束、产物、验收标准。
- 建立黄金任务集和人工路由基线。

**完成标准：** 每类任务都能判断成功、失败或需人工。

### M1：Agent 能力自动画像

解决用户描述粗粒度、平台无法准确路由的问题。

- 建立 `Agent Manifest`：能力、输入输出、前置条件、限制、成本、延迟、版本、负责人。
- Agent 上传后自动执行：接口解析 → 探测任务生成 → 沙箱调用 → 结果验证 → Profile 生成。
- 画像记录证据和置信度：声明能力 < 认证能力 < 生产观测能力。
- 重点识别“不支持什么”和失败边界，而不只是生成更好的文案。

**完成标准：** Agent 可被结构化检索、校验和比较；版本变更可重新认证。

### M2：Agent 路由与组合

- 先按输入、项目、版本、权限、资源和 SLA 做硬约束过滤。
- 再按任务匹配度、历史质量、成本、延迟和可用性排序。
- 已知任务使用规则和模板；模糊任务由 LLM 在候选集内规划。
- 支持降级、备用 Agent、人工指定和路由解释。

**完成标准：** 重点任务错误派发下降，平台交付率优于直接调用基线。

### M3：长链路可靠编排

- 使用持久化工作流/状态机，不依赖对话上下文保存状态。
- 每个步骤具备输入输出契约、检查点、超时、重试和幂等 Key。
- 支持局部重跑、失败降级、人工接管和完整重放。
- 每一步完成后验证产物，再进入下一步。

**完成标准：** 进程、Agent 或局部步骤失败后可恢复；无状态丢失和重复副作用。

### M4：规划准确性与闭环优化

- 用工作流模板覆盖已知流程；LLM 只补充参数、分支和新任务计划。
- 计划输出为结构化 `Plan IR`，包含输入、输出、前置条件、验收条件和失败分支。
- 采用混合规划：DAG/状态机负责全局依赖与恢复，ReAct 负责节点内的动态探索。
- 执行前做 Schema、资源、权限和成本校验；执行中采用“观察—验证—重规划”。
- 汇总生产成功率、人工接管率、成本、延迟和失败模式，持续优化路由。

**完成标准：** 计划可执行、失败可定位、结果可验收，并持续提升有效交付率。

## 推荐实施顺序

```text
任务定义 → Agent 契约 → 自动能力画像 → 规则路由
→ 持久化编排 → DAG/状态机骨架 → ReAct 节点执行 → 生产反馈优化
```

## 关键判断

LLM 可以总结和规划，但 Agent 的真实能力必须由接口、认证测试和生产数据共同证明。路由优化的最终指标不是“选对 Agent”，而是“任务被业务接受并完成交付”。

## 规划架构原则

不要在纯 ReAct 和纯 DAG 之间二选一：

- 确定的流程使用 DAG/状态机，负责依赖、并行、检查点、重试和恢复。
- 不确定的步骤使用 ReAct，负责观察、推理、行动和动态探索。
- 执行过程中根据观测结果更新任务图，而不是要求 LLM 一次性生成完整流程。

即：**工作流图是骨架，ReAct Agent 是节点内的执行策略，验证器负责判断节点是否完成。**
